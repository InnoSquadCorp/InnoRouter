# 7.0 persistence and shared resource admission

This implementation is a development contract, not a completed release or a
calibrated performance claim. Its fixtures are synthetic. Actual consumer
migration data, the technical scorecard, native Apple gates and release
acceptance remain separate requirements.

## One authority and two explicit formats

`RouterGraphSnapshotCodec<Route>` persists a flat, stable-key graph without
requiring runtime routes to be Codable. A route codec explicitly supplies its
stable key, payload version, byte encoder and decoder. The library format
version is independent of the application's schema ID/version. Migration chains
must be adjacent and every intermediate output is bounded before the next hop.

`RouterStore.snapshot(using:)`, `restore(from:using:)`, and
`RouterRestorationDriver(store:graphCodec:storage:)` use the same Store, codec
executor, storage executor, durability ordering and partial-restoration planner
as legacy persistence. They do not create another Store or apply state outside
normal current authorization, policy and lifetime admission. An activation's
authorization generation is captured before its worker can suspend or load.
Equal restored state still replaces runtime ownership; old scope handles and
presentation waiters do not regain authority from persisted IDs.

The legacy `RouterSnapshotCodec<Route>` remains explicitly selected and keeps
its actual app schema version. `RouterLegacySnapshotAdapter(codec:transform:)`
provides an opt-in route/state migration into a graph codec. No app version is
assumed to be one. A graph-format marker, even malformed, prevents fallback to
legacy decoding. Decoder/migration failures preserve the original bytes.

## Resource owners compose by intersection

`RouterResourceBudget` carries structure, byte, execution, logical JSON work and
transport-owner settings. Its codec, file-storage, scenario, Inspector and
pending-link conveniences validate raw configuration before deriving limits.
Invalid values are rejected, not normalized into a different valid budget.

Store-owned graph and legacy snapshot operations intersect the supplied codec
with the Store's budget. Increasing one owner cannot silently widen the other.
The same rule carries the owner's legacy JSON depth through a graph fallback.
Standalone codec opt-outs remain explicit; they do not bypass a finite Store.

File adapters must also be constructed with the chosen budget so oversized
files are rejected before reads/writes. A custom synchronous storage adapter
owns its allocation and I/O behavior; the Store cannot preempt arbitrary app
code or know a custom load's size before it returns. Received bytes are still
screened before route decoding. The documented bounds are not a claim that a
non-cooperative app codec or I/O operation can be forcibly stopped.

Legacy payload screening uses original JSON value spans, including escaped
strings and internal whitespace. It does not re-encode values to estimate
route bytes. Route counts, individual payload bytes and aggregate route bytes
are admitted before any application decoder. Writers validate their output
under the same shape/byte rules before returning bytes for storage.

JSON work is a cumulative logical ledger across syntax passes, isolated key
decodes, migrations and reserved application-decoder entry. Each output is
bounded before the next phase. These counts are not CPU time or peak RSS.
Inspector file classification and typed import share a single ledger instead
of resetting the budget at their boundary.

## Durable pending links

`RouterPendingLinkCodec` supports graph DTOs and an explicitly selected legacy
version-one reader/writer. A shared-budget initializer uses the budget's durable
lifetime and transport/work limits. Plan routes and gated/matched intent routes
share one aggregate route/payload budget. The legacy writer also screens exact
route spans so it cannot save data that its own reader would reject.

The durable record retains an origin and a last-observed timestamp. Saving,
restarting or replacing the driver does not renew the origin. Clock reversal,
invalid timestamps and expiry fail closed. Expiry is checked again after a
policy suspension before commit. Explicit `nil` lifetime opts out of age
expiry, but does not make malformed timestamps or clock reversal acceptable.

Historical legacy pending files without origin metadata reject by default.
`RouterLegacyPendingLinkTimestampPolicy.useKnownOrigin` is only for an actual,
trusted application-owned timestamp. Do not use decoding time as a guessed
origin. A restored pending link must revalidate its current URL origin, route
meaning/catalog and authorization; persisted approval is never trusted.

## Larger state and history

History's navigation projection removes presentations and badges while
preserving all admitted paths and IDs. It does not rebuild an explicitly
larger-budget state under the smaller provisional default, and uses no forced
`try`. History moves still enter the owning Store's normal admission pipeline.

## Evidence boundary

The Linux contracts compile actual platform-neutral product paths with named
adapter exclusions. Native rendering, native cancellation/presentation,
SwiftUI factory behavior, full Apple package builds and Instruments evidence
remain Apple gates. A source parse or a synthetic fixture is not native or
real-application validation. Provisional limits need calibration against real
consumer fixtures before release.
