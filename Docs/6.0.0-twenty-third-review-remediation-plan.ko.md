# InnoRouter 6.0.0 — 23차 수정 계획 및 실행 기록

기준: `cb1ca2f06833a554a3aacbae5a1f37464fcecfac`, 2026-09-16 KST.
범위: 사용자 승인에 따라 직전 검토의 코드 결함 2건과 실제 탐색 한계 경계 테스트를 순서대로 수정한다. 공개 API·최소 OS·macro-first 사용법은 유지한다. 이번 요청은 commit·push·tag·release를 포함하지 않는다.

## 문제와 선택

1. **F01 / P2 — 독립 nested resolve 격리 실패**: A의 feature B를 해석하는 동안 B의 파라미터 변환이 B의 다른 URL을 조회하면 부모 탐색의 순환 경로를 공유해 nil이 된다. 단독 B 조회는 성공한다.
   - 대안: 모든 child에 새 context를 주면 실제 feature cycle/budget 방어가 무력화된다. 대신 bridge가 허용한 generated entry에서 권한을 한 번만 소비하고, 직접 root에 남은 권한을 전달하지 않는다.
   - 실패 계약: 실제 feature cycle/ambiguity/한계 초과는 기존처럼 fail closed. 사용자 코드의 별도 조회와 그 코드가 생성한 Task는 독립 root를 갖는다.
2. **F02 / P2 — 오래된 remove의 status 덮어쓰기**: 삭제 I/O 정지 → 새 save encode 실패 → 삭제 완료 시 최신 failed 상태가 inactive로 사라진다.
   - 대안: 모든 I/O를 main actor에서 직렬 대기시키면 새 요청 수락과 반응성을 해친다. 대신 기존 save generation/storage epoch를 삭제에도 적용하여 I/O 결과 반환과 status 게시 권한을 분리한다.
   - 실패 계약: 이미 수락한 durable 삭제와 호출자에게 전달하는 오류는 유지한다. 새 save/remove/stop이 이전 상태 게시 권한을 무효화한다. 저장/삭제 실패는 navigation을 rollback하지 않는다.
3. **Q01 — 경계 증거/완료 판정**: production 깊이 63/64/65, 시도 1,023/1,024/1,025의 정확한 정상/초과 대조를 등록한다. 작은 주입값 테스트와 production 상수 검사는 이 행렬을 대신하지 않는다.

## 검증 방식

- 동시성 테스트는 sleep 횟수 대신 load/remove/save 진입 stream, 유한 storage barrier, 완료 Task의 정확한 결과를 사용한다. 실패 시 barrier·Task를 정리한다.
- F01은 실제 `@Router` 상호 feature 그래프와 사용자 정의 `DeepLinkParameterValue`를 사용한다. 테스트 전용 runtime 그래프만으로 macro 경로의 성공을 선언하지 않는다.
- 경계 테스트는 production limit 그대로, 서로 다른 concrete generic 타입의 유한 경로와 sibling 재진입을 사용한다. 순환 제외, 생성 root/feature bridge의 중복 진입 방지도 기존 macro 회귀와 함께 확인한다.
- F02 상태 판단은 기존 세대 의미를 확장하지 않는 최소 변경부터 적용한다. I/O 저장 순서와 status 소유권은 따로 단언한다.
- 새 공개 API를 추가하지 않으므로 baseline은 변경하지 않는다. baseline validator가 다르면 원인부터 확인한다.

## 이전 완료 판정 정정과 범위 밖 gate

[22차 계획](6.0.0-twenty-second-review-remediation-plan.ko.md)의 T11~T13 및 AC-034·038은 직전 검토의 반례로 재개방한다. T15의 포괄적인 로컬 완료 선언은 철회한다. 이 문서가 성공해도 아래 나머지 항목을 자동으로 완료 처리하지 않는다.

- AC-029의 실패 주입/cleanup 전체 행렬, AC-031의 새 native stop/restart·옛 lease callback 행렬.
- iOS Simulator 실제 root 재연결, 하한 Xcode 26.6/Swift 6.3.3 전체 실행, 실제 앱·기기·접근성 및 exact downstream revision.
- 이번 미커밋 후보의 exact SHA 원격 CI. 기존 `cb1ca2f0` CI와 구분한다.

기존 macOS NSHostingView 교체·공유 root 회귀는 전체 suite에 포함되며, 이를 새 native 행렬 전체의 증거로 확대하지 않는다. 배포 준비/발행 완료는 별도다.

## 실행 결과

통합 검증 중 기존 `unrelatedRestorationEventDoesNotReleaseActiveRoot`가 한 번의 `Task.yield()` 뒤 실행 slot 정리를 가정하여 실패했다. T19의 회귀 안정화에 이 테스트만 추가한다. stop이 해당 request ID를 취소했는지 즉시 단언하고 실제 slot 해제를 유한 대기한 뒤 후속 applied/state/revision을 검증한다. 제품 취소 코드는 변경하지 않는다.

ASan의 약 544 KiB cooperative-worker stack에서 최초 경계 fixture가 스택 guard에 닿았다. 테스트의 깊이 제어용 재귀 TaskLocal closure를 단일 fixture context로 옮기고, runtime의 이미 승인된 child는 추가 wrapping closure 없이 `withValue(nil, operation: body)`로 직접 실행하도록 했다. limit/검사/실행 actor를 바꾸지 않은 동일 30개 production 경계 조합이 ASan에서 통과했다. 실패 로그와 OS crash report를 보존한다.

기존 restoration 파일이 수정 후 source-lint의 550 유효 줄 제한을 넘어 공개 status/activation enum 두 개를 `RouterRestorationDriverTypes.swift`로 그대로 분리했다. 공개 선언과 동작은 변경하지 않는다.

### 후보 및 증거

- 도구: Xcode 27.0 (`27A5252f`), Apple Swift 6.4, arm64 macOS. `/Applications`에는 Xcode 27만 있어 하한 Xcode 26.6 전체 실행은 하지 않았다.
- 후보: 위 기준 SHA 위의 scoped dirty 변경. 이 문서만 제외한 변경·신규 파일의 `SHA-256 + 경로`를 경로순으로 합친 manifest hash는 `247bd48a2feffcaf4501ca87be9a4963efc841a5709c7f95287f36a5ac2c3fa6`다. 제품·테스트·gate·CHANGELOG·이전 문서 정정은 모두 포함한다.
- 원본 로그는 `.build/review23/`에 보존한다. ignored 로컬 산출물이므로 영구 회귀의 근거는 아래 등록된 테스트와 명령이다.
- F01은 수정 전 정확한 route 비교 1건이 실패했다. F02는 테스트 실행을 직렬화한 후 준비 오류 없이 9개 상태 assertion이 실패했고, 기존 정상 삭제 대조는 통과했다. 두 반례 모두 수정 후 성공한다.
