# Recursive presentation state groundwork

This change implements the portable value-model portion of plan sections 5.3
and 5.4. It is a partial S02/S04 foundation, not a completed native presentation
feature or an Apple-platform release gate.

## Implemented contract

- `RouterPresentation.node` owns a recursive `RouterNode`, defaulting to an
  empty stack. The existing route is the presentation's root destination.
- `RouterScopeComponent` distinguishes `.branch(RouterScopeID)` from
  `.presentation(UUID)`. String literals still mean branches; no application
  scope name has reserved semantics. `appendingPresentation(_:)` enters the
  child node of an exact active presentation.
- `RouterAction.presentationScoped` and `inScope(_:)` route incremental actions
  through that boundary. Missing or stale presentation IDs fail explicitly.
- Child push/pop/nested presentation actions leave the parent stack and other
  branches/scenes unchanged. A covered parent stack remains blocked.
- Dismissing a presentation removes its entire value subtree. This statement
  concerns reducer state, not asynchronous waiter/request cleanup.
- Structural validation and retained presentation identity checks traverse
  every descendant across application, regular-window, and immersive trees.
  Retained IDs cannot move to another owner path or change their root payload,
  style, or fixed options. Child navigation and selected detents may evolve.
- Feature node embedding/projection, feature action mapping, and deep-link
  authentication inspect recursive presentation children.
- Exact subtree replacement and the existing plan builder accept typed child
  paths while retaining the validated-state/draft boundary.

No random node instance IDs, runtime incarnation identities, or new public
store authority were introduced.

## Construction and migration

```swift
let modalID = UUID()
let initial = try RouterState<AppRoute>(
    root: .stack(path: [.home], presentation: .init(
        id: modalID,
        route: .editor,
        style: .sheet,
        node: .stack()
    ))
)
let child = RouterScopePath.root.appendingPresentation(modalID)
let next = try RouterReducer.reduce(.push(.details).inScope(child), from: initial)
```

Use `.branch(id)` when constructing a path from a `RouterScopeID` variable;
`RouterScopePath(["main", .presentation(modalID)])` remains concise. Code that
assumed `components` was `[RouterScopeID]` must handle both typed cases.

Legacy route-only presentation JSON without `node` decodes to an empty child
stack. Empty children are omitted when encoding, preserving the existing leaf
representation. Nonempty children round trip. The typed path decoder accepts
legacy `{ "rawValue": "main" }` branch components; the new writer emits explicit
branch/presentation keys. This compatibility path is not the new bounded graph
snapshot format or a substitute for its ingress validation.

## Verification

`RouterRecursivePresentationPortableContractTests` contains 14 deterministic
contracts covering nested actions, parent/sibling/scene isolation, boundary
escape rejection, exact replacement, stale callbacks, descendant duplicate IDs,
identity continuity, legacy leaf encoding, recursive Codable, plan construction,
feature parity, and protected descendant routes in all scene domains.

Run the narrow production Core/DeepLink harness with a distinct scratch path:

```sh
python3 scripts/run-portable-contracts.py --scratch /tmp/router-recursive-contracts
```

The harness records source/test hashes and every substitution. Its OSLog shim
and Apple-capability compilation-guard replacement do not simulate native
platform behavior. Three focused negative controls remove only descendant
validation, identity traversal, or authentication traversal; each must compile
and then fail its corresponding behavioral assertion. These are mutation
controls, not a claim that new APIs compile against the previous release.

## Integration and remaining work

Inspector projection/diff includes redacted child structure. Partial restoration
validates retained child routes at typed scope locations. Native action metadata
follows presentation boundaries. These Apple-target integration edits received
syntax parsing on Linux; Apple SDK typechecking and runtime tests remain open.

The existing history navigation projection intentionally omits presentations,
so its established contract is unchanged. Native recursive stack/container
rendering, presentation-aware scope lifetimes, parent-close descendant waiter
cancellation, deferred request cleanup, typed result races, alert/dialog family,
platform adaptation, mounted UI tests, API baselines, and complete S04 acceptance
remain unfinished. In particular, the legacy Store waiter traversal must be
redesigned rather than merely collecting nested IDs and reporting every removed
waiter as dismissed. Do not advertise this portable foundation as a complete
recursive native modal implementation.
