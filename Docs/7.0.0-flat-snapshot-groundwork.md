# Opt-in flat snapshot groundwork

This is partial S05/S06 implementation, not completion of persistence migration,
resource calibration, pilot acceptance, or release validation.

## Current boundary

`RouterGraphSnapshotCodec<R: Route>` serializes the existing canonical
`RouterState`; it owns no mutable navigation authority and introduces no store.
It is opt-in. Existing `RouterSnapshotCodec<R: Route & Codable>`, restoration
coordinators, file storage, and pending-link persistence continue to use their
existing paths. A caller can decode to state, build a plan, and use the existing
admission path, but this file does not claim a fully integrated replacement.

The new envelope separates:

- Library format version (currently 1 only)
- Application-owned schema ID and positive schema version
- Bounded flat-graph JSON payload

Application schema versions are not assumed to start at 1. The contract tests
use schema 7 and migrations 7 → 8 → 9 deliberately. Unsupported library formats
fail closed; no speculative historical format adapter is supplied.

Flat node, route, and presentation tables contain file-local references. The
encoder assigns deterministic traversal references such as `n0` and `r0`.
These references are not stable app declarations or live node-incarnation IDs.
Scope, window, immersive-space, and presentation IDs retain their existing
state semantics. No auth grants, execution closures, task handles, result
waiters, or runtime lifetime generations are serialized or recreated.

## Explicit app-owned route codec

`RouterGraphRouteCodec` requires a registry of stable route keys and current
payload versions plus encode/decode closures. It does not infer keys from Swift
enum names. Routes need not conform to `Codable`. Payloads are opaque bounded
bytes; the application chooses their representation.

All keys and payload versions are checked before the first app decode callback.
An unknown key or unsupported payload version fails the whole decode. An app
schema migration must explicitly rename old keys or translate old payloads.
No generic enum-case migration can determine an app's intended route semantics.
Application closure errors are mapped to redacted typed failures; their error
text and route payloads are not included in errors.

Closures are synchronous application code. Their execution time and temporary
allocations cannot be forcibly capped or preempted by this codec. The codec
checks returned bytes; apps must keep codec and migration work bounded too.

## Validation order and failure behavior

1. Check encoded byte count before envelope JSON parsing
2. Iteratively preflight complete JSON syntax, nesting and lexical tokens
3. Reject duplicate JSON keys, including escaped aliases
4. Read envelope and reject mismatched/future schema or unsupported format
5. Check decoded payload bytes and preflight its JSON before DTO decoding
6. Bound tables, path lengths, route payloads, graph and modal depths
7. Reject duplicate records, dangling references, cycles (including detached
   cycles), multiply owned records, and orphan records
8. Validate container selections, split mappings, badges, presentation options,
   and complete state structure with placeholder routes
9. For each adjacent app-schema migration, repeat steps 5–8 on its output before
   invoking the next transform
10. Check every stable key/version, decode every route, then construct and
    validate the final state before returning it

Encoding walks the tree iteratively and checks topology bounds before invoking
app encoding or recursive state validation. Encoded JSON uses stable table
traversal and sorted keys; repeatable output also requires deterministic app
codec closures. Equal route values have separate owned records, so
route identity does not rely on Swift's randomized hashes.

Failures never return partial state. `Data` inputs are immutable values, and this
codec never writes storage. Therefore a decode/migration failure leaves the
original bytes unchanged. This does not establish atomic saves, storage
cancellation/remove races, stale-write ordering, or pending-link integration.
Those require their existing storage paths and separate tests.

Catalog/host compatibility, current authorization, and policy checks remain the
caller's admission responsibility. A valid persisted graph is not permission to
navigate. Restoration must use the normal plan/admission path; restored modal
state does not authorize reconstructing old awaiting tasks.

## Provisional finite defaults

All limits must be positive; there is no accidental zero/unlimited mode. Apps
may explicitly select larger finite values, retaining responsibility for their
memory and stack implications.

| Limit | Provisional value |
| --- | ---: |
| Encoded envelope bytes | 4 MiB |
| Decoded graph JSON bytes | 2 MiB |
| One route payload | 64 KiB |
| JSON nesting | 32 |
| JSON lexical tokens | 262,144 |
| Nodes | 1,024 |
| Route records | 8,192 |
| Presentation records | 1,024 |
| Graph depth | 32 |
| One stack path | 256 |
| Presentation nesting | 8 |
| Windows | 32 |

JSON nesting counts arrays/objects with root depth one. Tokens include strings,
numbers, literals and every punctuation byte; whitespace is excluded. Graph
depth includes a scene-local root. Modal nesting counts presentation-child
edges independently of container edges. The envelope and decoded graph each
have their own JSON preflight under the same configured depth/token bounds.

These are uncalibrated starting values, including parser/table limits added for
this implementation. Tests establish inclusive boundaries and rejection, not
peak RSS, acceptable app workload distributions, performance equivalence, or
release-ready defaults. Base64 and bounded preflight temporary allocations
still contribute to peak memory. File adapters must enforce a read limit before
allocating a full file; checking an already materialized `Data` cannot do so.

## Verification and outstanding work

`RouterGraphSnapshotPortableContractTests.swift` contains explicitly synthetic
fixtures for complete tree round trips, app-schema migrations, corrupt graphs,
preflight complexity, and source-byte preservation. The portable runner copies
production Core sources, substitutes only its documented Apple-platform guard,
and records source hashes. It does not execute SwiftUI, native rendering,
store/auth admission, real files, Apple tests, or consumer-app adoption.

Still required: actual app-owned legacy schema/codec fixtures and adapters,
pending-link format adapter, storage integration and adversarial I/O races,
app catalog/host/auth admission integration, stable-key macro diagnostics,
representative workload/memory calibration, full package/API/native gates, and
actual pilot acceptance. No real legacy or pilot fixture was fabricated.
