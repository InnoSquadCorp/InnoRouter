# Partial-restoration planner verification

Verification narratives below were recovered from earlier work. They describe
historical scoped observations, not fresh evidence for this recovery commit.
See the recovery validation matrix for newly rerun exact-source results.

## Production boundary

`RouterPartialRestoration.swift` contains the actual Core/Foundation planner and
its public value types. `RouterStore+PartialRestoration.swift` contains the
unchanged Store adapter. The planner and moved Store-extension bodies were
compared byte-for-byte with commit `ab8e33f9` before testing.

`RouterTabRestorationTopology.swift` contains the actual structural value and
pure reconciliation. The catalog/of initializers moved to
`RouterTabRestorationTopology+Catalog.swift`, preserving their public names,
signatures and implementation. Its existing validated initializer became
internal so the same-module adapter can use it. No new public entry point or
alternate Store is introduced.

## Executable gate

Run from the repository with Swift 6.3+; the recorded Linux run uses Swift 6.4:

```sh
python3 scripts/run-restoration-contracts.py \
  --scratch /tmp/innorouter-restoration-debug --warnings-as-errors
python3 scripts/run-restoration-contracts.py \
  --scratch /tmp/innorouter-restoration-release \
  --configuration release --warnings-as-errors
```

The runner compiles all real Core sources, the two exact pure restoration
sources, and the byte-identical contract tests in an isolated package. No Store,
SwiftUI, catalog, policy or authentication implementation is simulated.

The sole normal environment substitution changes Core's explicit non-Apple
`RouterPlatformCapabilities.current` compile-time error to an immediate runtime
failure. No test requests this property and no Apple capabilities are invented.
Each scratch directory retains `test.log` and `provenance.json`: toolchain,
source revision, dirty status, full command, every original/compiled source hash,
explicit substitutions, executed test count, exit code and post-run hash check.
Tests use `--jobs 2 --no-parallel` and independent scratch directories.

## Contract coverage

- Exact keep-all positive control; retained nested presentations validate at
  typed presentation/branch paths, including window and immersive domains
- Removed presentation/scene parents suppress descendant validation and fallback;
  independent siblings and scene state survive
- Keep/remove/replace report locations, reason codes and route-payload exclusion;
  report Codable round trip
- Dependent suffix removal without visiting the suffix; empty-path control;
  explicit missing/invalid fallback failures and revalidated fallback replacements
- Self/two-route cycles; exactly eight replacement edges allowed and a ninth
  rejected before the next route is invoked
- Value/timeout/cancellation first-winner races, pre-start cancellation, and
  cancellation while fallback is suspended; all controlled losing operations
  are subsequently released and drained
- Topology empty/duplicate inputs, exact-state control, insertion/reordering,
  original orphan order and data, badge/scene preservation, selection fallback,
  still-current selection, root mismatch and current-tab stack requirement
- Composition of the real topology and planner functions, with no invented
  routes in inserted empty tabs

Three deterministic staged-only mutations verify that the contract tests detect
lost presentation children, a changed replacement bound, and discarded orphan
branches. For example:

```sh
python3 scripts/run-restoration-contracts.py \
  --scratch /tmp/innorouter-restoration-mutant \
  --mutation skip-presentation-children --warnings-as-errors
```

Mutation runs are expected to exit nonzero due to semantic assertions after a
successful compilation. They are sensitivity controls, not historical defect
reproductions. Unrelated positive controls must continue to pass. Production
source files are never mutated by this option.

## Important limits

A timeout or cancellation logically finishes planning and returns no partial
candidate/report. It requests cancellation of validator work; it cannot force a
noncooperative validator to exit. The tests intentionally keep such work alive
after the terminal result, then release it explicitly and confirm that the late
result does not replace the terminal. Planning currently supplies no operation
registry reservation. These tests do not establish an active-validator bound or
extend policy-operation bound evidence to validators. A synchronous MainActor
blocker can also prevent the timeout from running.

Framework-generated report entries do not automatically include route payloads.
Application-provided reason strings and structural identifiers are preserved;
they are not sanitized. Applications must provide nonsensitive reason codes and
identifiers. This is not a guarantee that arbitrary application text is redacted.

This gate verifies preparation, not actual Store application, revision changes,
policy/authentication admission, live presentation waiter cleanup, catalog
adapters, native hosts, platform UI, full-product dependency graph, minimum
Swift-toolchain compatibility, performance, consumer adoption or release
readiness. Those require their own evidence. A no-partial-return assertion here
must not be described as proof of atomic Store commit.
