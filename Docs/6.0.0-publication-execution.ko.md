# InnoRouter 6.0.0 배포 실행

시작: 2026-09-16, 기준 HEAD `e6099d3bf4d474a4f2afa153147669cc3a893854`.
사용자 승인: 남은 수정·검증을 순서대로 수행하고 6.0.0 정식 배포까지 진행.

## 설계와 제한

- 문제: 최신 R24 수정은 로컬 검증만 완료됐고, 이전 원격 HEAD의 Xcode 26.6 / Swift 6.3.3 ASan 실행이 signal 4로 종료됐다. native 수명주기·실패 정리 증거와 배포 문서도 남아 있다.
- 제약: macro-first, 공개 제품 3개, Swift 6.3 및 OS 하한 유지. 기존 수정 보존. 실패 테스트·sanitizer·배포 gate를 끄거나 기준을 낮추지 않는다.
- 대안: 로컬 Swift 6.4 성공으로 즉시 태그를 만들기 / 정확한 후보를 원격 하한 toolchain과 native 경로에서 검증한 후 태그 만들기.
- 선택: 후자를 선택한다. CI 성공만으로 미실행 native 인수 조건을 완료 처리하지 않는다. 이 실행 문서의 존재도 배포 승인이 아니다.
- 실패 동작: 원인 미확정 충돌 또는 필수 gate 실패가 남으면 정식 태그·발행을 보류한다. crash report와 원래 exit code를 보존하고 원인을 좁힌다. 이미 공개한 태그를 강제 이동하지 않는다.
- 검증: 아래 단계별 exact SHA·로그·통과/실패/미실행을 연결한다. push마다 원격 parity와 작업 트리를 확인한 뒤 지정된 XcodeBuildMCP cleanup을 실행한다.

## 실행 순서

1. ASan 원래 실패 로그 보존, 같은 SHA 재실행 및 진단. 필요하면 실패 산출물 수집을 추가한다.
2. R24 상태 소유권 수정과 진단 보강을 검증·커밋·푸시하고 하한 도구체인에서 확인한다.
3. AC-029 실패/정리 및 AC-031 mounted stop/restart·옛 callback 경계를 검증하고 필요한 수정을 한다. iOS root 재연결, native scene 검증, exact downstream consumer를 구분한다.
4. README·fixture version·배포 체크리스트를 현재 사실에 맞추고, 최종 소스 후보의 local/remote 필수 gate를 모두 통과시킨다.
5. CHANGELOG를 6.0.0으로 cut하고 release commit의 gate를 확인한다. 이후에만 `6.0.0` 태그를 push한다.
6. release workflow, GitHub Release, 버전별/latest DocC, exact tag 소비와 원격 branch/tag 일치를 확인한다.

## 실행 기록

- 최초 작업 트리: R24 소스·테스트·sanitizer 등록·CHANGELOG·기록 문서 6개. 다른 사용자 변경 없음.
- 원래 ASan 실패: run `35061610717`, attempt 1, address job `104682919193`, signal 4. Thread Sanitizer는 성공. 원본 로그는 `.build/release600/asan-original-failure.log`에 보존했다.
- 같은 SHA의 실패 job 재실행을 요청했다. 이 재실행은 아직 미커밋 R24 수정본의 증거가 아니다.
- R24 수정은 `8c610325`로 커밋했다. 직전 전체 local gate에 더해 관련 16 tests / 3 suites와 source lint를 다시 통과했다.
- 원래 SHA의 ASan attempt 2도 실패했다. 재현 로그는 `.build/release600/asan-repeat-failure.log`에 보존한다. 우연한 한 번의 실패로 무시하지 않는다.
- sanitizer CI에 pipefail을 유지한 로그 보존, 제한된 테스트 프로세스 crash report 수집, artifact 업로드를 추가했다. 실패를 성공으로 바꾸는 옵션이나 자동 retry는 추가하지 않았다. YAML parse와 source lint 통과.

현재 상태: 실행 중. 정식 태그와 Release는 생성하지 않았다.
