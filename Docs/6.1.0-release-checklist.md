# InnoRouter 6.1.0 release checklist

This checklist accompanies the 6.1.0 release cut. The exact published commit,
workflow outcome, and site state must be taken from the tag and release run;
this source document does not claim that publication has already happened.

## Scope and compatibility

- Snapshot envelope/payload/file limits remain opt-in.
- Partial restoration, tab topology, and explicit `@TabItem` identity extend
  the existing 6.0 APIs. Exact restoration remains the default.
- Automatic saves revoked before storage execution cannot overwrite a newer
  snapshot. Explicit saves preserve their accepted durability contract.
- Swift 6.3 and the existing Apple platform minimums are unchanged.
- `DeepLinkMatcher.diagnostics` remains readable with the same results and is
  computed on demand; callers repeatedly reading it should retain that value.

## Release gates

- [x] Runtime identity and both README installation versions say 6.1.0.
- [x] CHANGELOG has a dated 6.1.0 section and a fresh Unreleased section.
- [x] The publication workflow passes its candidate version and channel into
  the identity gate. GA and prerelease changelog policies are tested separately.
- [x] GA publication checks the remote consumer's resolved version and commit
  against the immutable commit resolved during tag preflight.
- [x] Local principle gates, all platform builds, and native scene probes.
- [x] Inspector preparation regression and full native UI flows.
- [ ] All 24 required checks on the final PR head and merged main commit.
- [ ] Bare `6.1.0` tag points to the verified main commit.
- [ ] Release workflow and exact tagged consumer pass before publication.
- [ ] GitHub Release, versioned DocC, and `/latest/` resolve to 6.1.0.

The last four items are recorded by GitHub's immutable commit/run evidence and
the publication completion report, after this document is committed.

## Follow-up quality work

The first Inspector run on `bbff67cb` timed out after a test-fixture switch tap;
the same source passed on retry. Its xcresult identified a nested native switch
whose value stayed at zero after a correctly positioned tap. A retry passing
does not prove the underlying simulator cause is fixed.

The fixture now uses idempotent Hold/Resume commands with a visible model-state
acknowledgement. The new policy-preparation regression also checks the real
Inspector's held/cancelled/applied outcomes; existing localization and user-flow
assertions remain. The earlier native switch failure was not reproduced in two
local baseline runs, so this removes that fixture dependency without claiming
to have diagnosed or repaired the simulator's internal behavior.

Local validation used Xcode 27.0 / Swift 6.4: 695 package tests in 88 suites
(one existing intentional known issue), public API/DocC/downstream gates,
all platform builds, macOS and iPadOS native scene probes, five fresh-process
Inspector preparation runs, and all three full Inspector UI tests passed.
Remote checks independently use pinned Xcode 26.6 / Swift 6.3.

The visionOS 26.5 combined probe exposed a native scene creation error after
rapid reuse; it occurred on the base source as well and in a SwiftUI-only
control app. Each independent allow/reject/cancel case now uses a fresh probe
installation and process. Three sets (nine policy cases) passed with every
policy assertion retained. Process restart alone was insufficient. No router runtime fix or
retry-on-failure was introduced for that system error. The combined sequence
remains available as a stress probe, and pinned CI now runs the native probes.

Broader load/decode/validator/policy cancellation combinations, execution on
every minimum supported OS and physical devices, and comparable CI performance
measurements remain follow-up work. The iOS 18.6 restoration process probe is
evidence for that runtime, not all platform minimums. No CI speed improvement
is claimed from samples with different product sources.
