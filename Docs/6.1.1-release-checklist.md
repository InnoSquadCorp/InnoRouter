# InnoRouter 6.1.1 candidate checklist (historical)

This planned patch release was superseded by the direct 7.0.0 development cycle.
The checked items below are historical candidate observations, not verification
of the current 7.0 sources. Use [the 7.0 checklist](7.0.0-release-checklist.md).

This checklist accompanies the 6.1.1 patch release cut. The exact published
commit, workflow outcome, and site state must be taken from the tag and release
run; this source document does not claim that publication has already happened.

## Scope and compatibility

- No public symbol is added, removed, or changed. The three public API
  baselines and symbol budgets are unchanged.
- `@TabItem` default scope IDs equal the generated `Tab` raw value in both
  expansion paths. Only a router that combines a backticked tab case with a
  sibling `id:` expands differently; its 6.1.0 snapshots keep that branch as an
  orphan unless the tab declares the old spelling with `id:`.
- `RouterTabHost(store:)` pushes default links into the tab it displays, and
  selects that tab in the same transition when the stored selection is orphaned.
- The supplied-store tab and split host initializers render a mismatched root
  instead of trapping, and log one warning per host type. Over a root of
  another shape their content binds to an unresolvable scope, and their
  default links and a tab host's tab bar selection are rejected, so nothing in
  the host writes into that root.
  Exact restoration still applies any root shape, as pinned by the restoration
  boundary tests.
- `RouterRestorationDriver` applies `RouterSnapshotRecoveryPolicy` to a typed
  storage rejection and restores the fallback through normal policies. `.fail`
  and untyped storage errors keep their 6.1.0 behavior; the partial-validation
  driver still applies no recovery.
- `swift-syntax` admits `"603.0.2"..<"605.0.0"`. The committed resolution uses
  604.0.0 across all three live locks; the platform workspace resolves the newest admitted line.
- Swift 6.3 and the existing Apple platform minimums are unchanged.
- 6.1.0's three `RouterSnapshotError` cases remain, recorded as a known source
  issue, and `RELEASING.md` now classifies enum case additions as breaking.

## Follow-up quality work

The 6.1.0 release run failed its first attempt on two jobs. The visionOS job
timed out in `simctl bootstatus`; boots now shut down, erase, and retry. The
Inspector UI job timed out waiting for the fixture's locale label after a
synthesized tap on `probe.locale.ko` at the button's center; the label stayed
`Locale en` for five seconds after the app went idle, which points to a lost
fixture tap rather than slow rendering. The same test had failed three earlier
first attempts on the nested switch the 6.1.0 fixture change removed. Splitting
the scenarios and printing recorded assertions make the next failure cheaper
and diagnosable; they do not prove the lost-tap cause is gone. No retry or
longer timeout was added.

Topology reconciliation failures (`rootIsNotTabs`, `expectedStack`) still
bypass `RouterSnapshotRecoveryPolicy.use`. Expressing them to the recovery
closure needs a new `RouterSnapshotError` case, which the corrected policy
defers to the next major release.

Dependabot PR #50 moves the swift-syntax floor to 604.0.0 and is superseded by
the widened range.
