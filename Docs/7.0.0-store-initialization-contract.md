# 7.0 Store initialization and resource admission

Input-bearing construction throws. An invalid supplied state is never replaced
with an empty state, partially admitted, or silently given a larger budget.

```swift
let empty = RouterStore<AppRoute>()
let macroFirst = AppRoute.makeRouterStore()
let configured = try AppRoute.makeRouterStore(configuration: .init())
let restored = try RouterStore(initialState: savedState)
let populated = try RouterStore(initialPath: [AppRoute.settings])
```

The two zero-argument factories are genuinely nonthrowing. They construct a
known-valid empty root stack using the finite provisional defaults. They do not
catch errors from user input and do not use a forced `try`.

`@Router` supplies `DestinationRoute` conformance; `makeRouterStore` is provided
by that protocol's extension, not generated per enum. Its default topology
remains an empty root stack. It does not infer tabs or split columns from route
cases. `RouterTabHost` and the split hosts continue constructing their complete
catalog/layout topology. Their input-bearing constructors now throw, including
when that topology exceeds the selected resource budget. Existing stores can be
passed to hosts without reconstructing their navigation tree.

A large static tab declaration can still compile. Building its tab host under a
too-small budget fails with `RouterResourceLimitFailure`; declaration size is
not hidden by removing tabs, choosing a different root, or increasing limits.
Choose a larger measured finite budget explicitly, or `.unlimited` to accept
operation outside bounded-resource guarantees. The macro's existing catalog
identity diagnostics remain unchanged.

```swift
let limits = try RouterGraphSnapshotLimits(maximumNodes: 2_048)
let configuration = RouterStoreConfiguration<AppRoute>(
    resourceBudget: RouterResourceBudget(snapshot: limits)
)
let host = try RouterTabHost(AppRoute.self, initial: .home, configuration: configuration)
```

## Admission order and atomicity

- Store initialization performs iterative resource admission before recursive
  structural validation, scene-catalog checks, or scope-lifetime construction
- Initial paths are built through `RouterStateDraft.build(resourceBudget:)`
- Request admission happens before queueing or publishing the original action
  to request observers. Oversized input emits only a redacted terminal rejection
- Reducer dispatch validates the current state and the action before recursion;
  after applying to a local value it checks the complete candidate before
  recursive structural validation and identity-continuity checks
- Resource failure becomes `.resourceLimit(RouterResourceLimitFailure)` and
  invokes no policy, commits no state, and does not increment revision
- Removing state releases structural capacity; validation retains no reservation

`RouterState.rootStack(path:)` remains a structurally valid value constructor.
It is not proof of resource admission. Store and reducer boundaries check its
whole path, including values built before a narrower configuration was chosen.

## Execution settings

`RouterStoreConfiguration(resourceBudget:)` installs the Store-owned parts of
one budget. Existing queue, deferral, policy, and restoration count properties
remain writable aliases reflected by `configuration.resourceBudget`. Replacing
that budget preserves the configured queue and deferral overflow strategies.

Provisional defaults are a 256-request queue, 64 deferrals, 64 active
policy/authorization operations, eight active restoration operations, a
30-second policy/authorization timeout, and a 15-minute deferral lifetime.
Explicit `nil` deadlines or active-operation counts still opt out. Negative
legacy counts, deadlines, and event-buffer sizes are invalid input and throw
`RouterStoreConfigurationFailure`; zero and explicit `nil` keep their distinct
meanings. Timed-out or cancelled asynchronous
operations keep their capacity reservation until the application work actually
exits; deadlines do not preempt synchronous application code.

These values are uncalibrated development defaults, not RSS or wall-clock
performance guarantees. Route payload memory is opaque at state admission;
codec boundaries separately enforce their byte limits. An explicit unlimited
budget is outside finite-resource guarantees.

## Migration and validation scope

Use `try` in an application setup boundary and surface initialization errors
there. Do not wrap configuration or restored data in `try!`, suppress errors
with `try?`, or substitute another navigation state. Build an owned Store before
a nonthrowing SwiftUI `body` and inject it when setup can fail.

`RouterHost(Route.self) { ... }` retains its nonthrowing empty convenience.
Supplying an initial path or configuration requires its throwing overload.
Tab/split constructors with catalog, selection, paths, layout, or configuration
also throw. No native rendering behavior is proven by the Linux Store-engine
contracts; Apple host/compiler and macro behavior suites remain separate gates.

Plan-builder construction has a finite default and an explicit
`RouterPlan(from:resourceBudget:_:)` overload. Store and environment transactions
forward their owner's budget; default tab/split link planners do the same.
Final root/scene replacements are resource-checked before recursive validation.

Feature-scoped action/plan input is resource-admitted before route embedding or
child structural validation. Subtree replacement checks both the bounded scope
path and input node before recursion, then the whole candidate before structural
validation. Projected handles forward the same immutable owner budget.

Shared budget values retain invalid raw input. `validateConfiguration()` reports
`RouterResourceLimitFailure.Code.invalidConfiguration`; `minimum` and `maximum`
state the permitted integer range. Negative duration diagnostics identify the
offending seconds or attoseconds component. No invalid limit becomes a larger
valid value through normalization.
