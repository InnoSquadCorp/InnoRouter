# 7.0 Inspector non-UI contracts

The original verification counts below are historical slice observations.
Current recovery runs have separate exact-source records; historical counts do
not establish a current whole-package pass.

## Implemented boundary

Inspector projection now traverses presentation-owned child nodes. A root modal
and its nested modal receive the redacted paths `/presentation` and
`/presentation/presentation`; container descendants add `branch[n]` components.
Paths retain structural position without copying branch IDs, presentation UUIDs,
scene IDs, or route payloads. Window and immersive content retain distinct path
prefixes. Default event summaries include descendant stack, route and
presentation counts.

Projection, structural diff, pure reducer replay, snapshot/bundle import/export,
recording, playback, timeline selection/filtering, scenario-controller state,
and catalog localization are compiled from production sources in the portable
gate. `RouterInspectorRecorder.attach(to: RouterStore)` is isolated in
`RouterInspectorStoreAdapter.swift` without changing its public signature.
There is no replacement Store, fake SwiftUI, or platform simulation.

The unchanged catalog is loaded as actual JSON. Darwin keeps its native
`String(localized:)` and `Bundle.preferredLocalizations` behavior. Corelibs
Foundation uses catalog language/script matching via `Locale.Language`, because
its Bundle implementation in the verified toolchain did not honor explicit
language preferences. All 66 reviewed keys and 15 translated languages plus the
English source fallback are exercised, including region/script matching.

## Bounded import

Encoded imports now run the same package-access iterative JSON checker as flat
graph snapshots. The public graph error mapping is unchanged. Inspector maps
JSON complexity failures into its own typed errors before using the caller's
`JSONDecoder`:

- Existing encoded-byte bound: 8 MiB
- Existing entry-count bound: 5,000
- New configurable JSON container-depth bound: 64
- New configurable lexical-token bound: 524,288

These are implementation safety budgets, **not empirically calibrated
application or release defaults**. Depth counts both object and array containers
with the root at depth one. Token accounting includes scalar values, property
names and structural punctuation. Unknown fields are included in the full
syntax/depth/token scan. Duplicate keys, including escaped aliases, fail closed
throughout the document. Size is rejected before making the scanner's byte
copy; only bounded isolated property-name strings reach Foundation during the
scanner's duplicate-key phase. Entry-count checks still precede entry decoding.

`jsonDepthExceeded(actualDepth:maximumDepth:)` and
`jsonTokenLimitExceeded(actualCount:maximumCount:)` are new Inspector import
errors. Malformed syntax and duplicate JSON keys map to
`malformedSnapshotEnvelope`. Existing byte/count and duplicate-entry errors
remain intact. Unsupported bundle format versions and unknown enum codes are
rejected, and every tested failure preserves entries and bookmarks atomically.

The recorder's capacity bounds retained entry count, bookmarks and live timing
correlation. It does not bound the bytes in an application-supplied custom
formatter's metadata, or the size of a directly supplied in-memory snapshot.
Encoded import bounds do not constitute a general process-memory limit. Export retains the recorder's entry-count bound and now defaults to a separate
provisional 8 MiB encoded-export cap. Explicit nil opts out. This is not a
streaming-export or total transient-allocation bound.

## Reproduce

```sh
python3 scripts/run-inspector-contracts.py --scratch /tmp/router-inspector-debug \
  --warnings-as-errors
python3 scripts/run-inspector-contracts.py --scratch /tmp/router-inspector-release \
  --configuration release --warnings-as-errors
python3 scripts/run-portable-contracts.py --scratch /tmp/router-core-regression
python3 scripts/check-inspector-localization.py
```

Use Swift 6.3 or newer; recorded execution uses Swift 6.4.0 on Linux. The runner
stages exact production/test/resource bytes and records their SHA-256 values,
toolchain, command, exit code, and a post-run source-match check in
`provenance.json`. The sole source substitution changes Core's unsupported-Apple-
platform compilation guard to a failing precondition. Tests provide platform
metadata explicitly and never enter that precondition. `test.log` retains the
complete run. The generated isolated package copies the catalog as a resource;
it does not claim to validate Xcode's compiled localization resources.

Coverage comprises 35 tests across five suites:

- Existing 2,000-mutation snapshot corpus and 2,000-mutation bundle corpus
- Existing timeline filtering, stepping, selection invalidation and eviction
- Existing diagnostic bundle round-trip, format rejection, envelope and entry
  limits, duplicate append atomicity, timing reset and orphan-bookmark cleanup
- Existing complete localization catalog and locale-switching tests
- Nested modal/container/scene projection with unique payload-redacted IDs,
  precise child diffs, actual reducer replay parity/mismatch/rejection, default
  policy-message redaction, deterministic nested bundle export/reopen/playback
- Exact JSON depth/token boundaries, entry/byte checks before a supplied decoder,
  malformed/duplicate unknown fields, unknown entry codes, 50,000 nested unknown
  arrays rejected at depth 65, 10,000-record retention and timing eviction,
  bounded append/replace bookmarks, pause-on-rejection and manual pause/resume

The shared checker refactor also passes 107 Core/DeepLink contracts, including
all 21 flat-graph snapshot contracts. Negative controls restore only the old
Inspector preflight while retaining the candidate API and the same test source:
depth, token and malformed/duplicate-field tests compile and fail because the
old checker lets the caller's decoder run or accepts the unsupported structure.
This isolates missing preflight enforcement rather than an unavailable API or
an unrelated setup failure.

## Remaining gates

This is an S08 non-UI implementation/verification slice. It does not complete
S08, verify native views or Store attachment, exercise policy execution through
a real Store, establish slow-subscriber behavior of the Store event bus, or run
the full package, Apple platforms, public-API extraction, downstream consumers,
representative app migrations, native restore lifetimes or release acceptance.
The new Inspector limit fields/error cases and initializer signature are
intentional API changes that require the native public-API baseline gate.
