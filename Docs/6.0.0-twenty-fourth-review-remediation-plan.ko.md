# InnoRouter 6.0.0 — 24차 수정 및 재검토

기준: `e6099d3bf4d474a4f2afa153147669cc3a893854`, 2026-09-16.
범위: 직전 R24-F01 상태 게시 소유권 결함 수정 및 주변 경로 재검토. commit/push/tag/release는 이번 요청에 포함하지 않는다.

## 문제와 설계

- 문제: activate는 activation generation, save/remove는 save generation/storage epoch만 검사한다. 서로의 새 작업을 알지 못해 이전 완료가 최신 loading/failed를 덮는다.
- 제약: macro-first·공개 API·최소 OS 유지. initial restore phase와 durable I/O acceptance order는 status와 별개로 유지한다. status 권한 상실만으로 이미 수락한 명시적 I/O나 호출자 결과를 취소하지 않는다.
- 대안 A: 모든 activate/save/remove를 하나의 직렬 큐에 넣는다. 반응성과 독립 encode·navigation 동작까지 바꾸므로 선택하지 않는다.
- 대안 B: 화면 status 게시에 공통 세대를 사용한다. 실제 activation/save/remove 시작과 stop이 새 소유권을 획득하고, 완료는 자기 소유권이 유효할 때만 게시한다. 이 최소 경계 변경을 선택한다.
- 자동 저장: debounce 예약 자체는 I/O 시작이 아니다. 실행 가능한 저장 시도가 시작할 때 status 소유권을 획득한다. 취소·대체된 자동 저장은 새 작업 상태를 덮지 않고 종료한다.
- 실패 시 동작: 최신 작업의 실패만 status로 게시한다. 오래된 작업의 오류는 원래 호출자에게 그대로 반환한다. activation의 결과/phase 정리와 표시 상태의 게시를 분리한다.

## 순서와 검증

1. 기존 3개 반례를 영구 회귀에 등록하고 수정 전 실패를 확인한다.
2. 공통 status 소유권을 적용하고 성공·실패·취소/stop·자동 저장 교차를 확장한다.
3. 같은 수명 경계의 주변 코드를 다시 검토한다. 새 가설은 재현 전 결함으로 집계하지 않는다.
4. focused 반복, 전체 테스트, lint/API/docs, 외부 consumer, TSan/ASan을 실행한다. 도구체인·미실행 플랫폼·현재 diff를 증거와 연결한다.

완료 기준: 원래 3개 상태 assertion과 확장 행렬 통과, 기존 durable ordering/restore phase/stop 회귀 보존, navigation state/revision 및 호출자 결과 보존, 새 공개 API 없음.

## 실행 기록

### 구현과 후보

- R24-F01을 수정했다. activation/save/remove/stop이 공통 `statusGeneration`을 사용하고, `status`의 모든 변경은 소유권을 검사하는 `publishStatus`를 통한다.
- `activationGeneration`·`initialRestorePhase`는 복원 수명, `saveGeneration`은 자동 저장 대체, `storageEpoch`·durability ticket은 삭제 후 쓰기 방지와 I/O 순서에 그대로 사용한다. 화면 상태 게시 권한으로 이 별도 계약을 대체하지 않는다.
- 명시적 save는 이전 activation의 실패 정리로 save generation이 바뀌어도 자신의 저장·실패 결과를 게시한다. 자동 save의 폐기 조건은 유지한다. 예약만 된 debounce는 status 소유권을 가져가지 않으며, background save의 오류를 중복 게시하지 않는다.
- source-size 기준을 유지하도록 View extension과 modifier를 `RouterStateRestorationModifier.swift`로 이동했다. 공개 extension부터 파일 끝까지의 본문 SHA-256은 이동 전후 모두 `fdeca5333a5d6a78eb12caa2fd885ecd25d685b5629a28482e824b8d22ad180f`이다. native UI 동작을 수정한 것으로 주장하지 않는다.
- 새 공개 심볼·API baseline 변경, macro 변경, 플랫폼 하한 변경은 없다. sanitizer 필터에는 새 회귀 suite를 추가했다.

후보는 위 HEAD에 다음 다섯 경로의 변경을 더한 작업 트리다. 이 기록 문서 자체는 manifest에서 제외한다. 파일 경로순으로 `shasum -a 256` 결과를 이어 붙인 manifest의 SHA-256은 `50f9f3dd0ebb8dc54001e63149f0046adf0440f51a53ad6c6d736c119222654c`이다.

### 수정 후 별도 재검토

같은 작성자가 public caller 관점에서 다시 검토했다. 제삼자 독립 리뷰는 아니다.

- restoration의 모든 status 쓰기, activation claim/lease·초기 복원 phase, stop/detach, 자동 저장 대체 및 오류 게시 경계를 확인했다.
- `RouterDurabilityGate`의 reserve/wait/finish 및 remove 무효화, snapshot/pending-link 저장 경계, Store의 request-family 취소·queue/deferral/presentation 완료 경로를 다시 읽었다.
- 인접 History의 generation/terminal waiter, Scene의 lifetime token/restoration ticket·immersive effect 직렬화도 확인했다. 이번 diff는 해당 계약을 변경하지 않는다.
- 이번 재검토에서 R24-F01 외에 새로 재현·확정한 독립 제품 결함은 없다. 테스트 성공이나 정적 검토를 미실행 경로의 무결함 보장으로 해석하지 않는다.
