사용자가 요청한 여섯 기능의 범위와 순서를 기록한 명세다. 기능은 6.0.0 이전에
구현되어 해당 버전에 배포됐다. 구현·배포 사실과 문서 승인 상태는 별도로 기록하며,
명시적 승인자가 없으므로 문서 상태는 Draft를 유지한다. 기존 요구사항 ID는 변경하지
않고 FR6-036부터 이어 쓴다.

## 목적과 현재 근거

앱이 커져도 기능 모듈을 독립적으로 개발하고, 복잡한 이동을 재현하며, 오래된
화면 상태를 복원하고, 사용자가 탐색 경로를 되짚을 수 있도록 한다.

| 구분 | 내용 / 근거 |
| --- | --- |
| 확인된 사실 | [RouterFeatureScope](../Sources/InnoRouterSwiftUI/RouterFeatureScope.swift)는 `@FeatureRoute`가 연결한 부모·자식 경로 타입을 하나의 부모 store에서 투영하고 요청한다. |
| 확인된 사실 | [CasePath](../Sources/InnoRouterCore/CasePath.swift)는 타입이 지정된 삽입·추출과 합성을 지원한다. 기능 모듈 연결의 기반으로 재사용할 수 있다. |
| 확인된 사실 | [RouterTestClock](../Sources/InnoRouterTesting/RouterTestClock.swift)과 `RouterTestStore`가 production timeout·queue·deferral 경로의 가상 시간과 요청 제어를 제공한다. |
| 확인된 사실 | [부분 복원](../Sources/InnoRouterSwiftUI/RouterPartialRestoration.swift)은 keep/remove/replace 계획과 payload-free 보고서를 만들고 정상 정책·revision 경로로 적용한다. |
| 확인된 사실 | 생성 deep-link catalog와 Inspector analyzer/UI가 경로 목록·순수 진단·명시적 실행을 분리한다. |
| 확인된 사실 | `RouterScenarioRecorder`와 source generator가 bounded fixture, 기대값, 테스트 생성을 제공한다. |
| 확인된 사실 | [RouterHistory](../Sources/InnoRouterSwiftUI/RouterHistory.swift)가 상한 있는 뒤로·앞으로·checkpoint 이동을 같은 store에서 제공한다. |
| 유지 조건 | 고급 기능은 앱의 명시적 선택이며 기존 간단한 매크로 사용법, 플랫폼 하한, 세 공개 제품을 유지한다. |
| 미확인 | 실제 앱별 계정·업무 데이터 유효성 공급자와 제품 통합 결과는 각 소비 앱이 별도로 검증한다. |

## 사용자 시나리오

| ID | 사용자에게 필요한 결과 |
| --- | --- |
| US6-001 | 계정 기능 개발자는 앱 전체 경로 타입을 가져오지 않고 자기 기능을 구현·테스트한다. |
| US6-002 | 앱 개발자는 실제 시간을 기다리지 않고 취소·시간 초과·대기 요청 만료를 검증한다. |
| US6-003 | 앱 사용자는 삭제된 상세 화면 때문에 다른 탭의 정상적인 방문 기록까지 잃지 않는다. |
| US6-004 | 앱 개발자는 URL이 처리되지 않은 이유와 예상 화면 변화를 한곳에서 확인한다. |
| US6-005 | 앱 개발자는 실제 발생한 이동을 재현 자료로 남기고, 원하는 동작을 검증하는 테스트로 전환한다. |
| US6-006 | 앱 사용자는 탐색 중 이전·다음 위치나 이름 있는 체크포인트로 이동한다. |

## 기능 요구사항

여섯 단계 모두 이번 개발 범위에 포함한다. 아래 요구사항의 우선순위는 모두 Must다.
별도 사용자 요청 없이 단계를 생략하거나 추가 기능으로 범위를 늘리지 않는다.

### 1. 기능 모듈별 경로 합성

| ID | 요구사항 |
| --- | --- |
| FR6-036 | 기능 모듈은 자체 `@Router` 경로만으로 선언·이동·상태 관찰·독립 테스트를 수행할 수 있어야 한다. 앱 조립 지점의 매크로 기반 연결로 부모 경로에 통합하며 기능 모듈은 앱 타입에 의존하지 않는다. |
| FR6-037 | 자식 요청은 부모의 동일한 정책·큐·전환 ID·커밋 경로를 거친다. 자식은 별도 가변 라우터 저장소를 만들지 않으며 자기 영역의 값 투영만 관찰한다. 자식 전체 계획도 형제 영역을 덮어쓸 수 없다. |
| FR6-038 | 중첩 합성, 같은 기능의 여러 인스턴스, 탭·분할 화면, 타입이 지정된 모달 결과, 기존 창·몰입 공간 안의 기능 영역을 지원한다. 잘못된 매핑·사라진 영역·충돌한 식별자는 명시적으로 실패한다. 전역 창 생성·종료 권한은 앱 조립 지점이 소유한다. |

### 2. 가상 시간과 동시성 시나리오 테스트

| ID | 요구사항 |
| --- | --- |
| FR6-039 | 외부 소비자는 `InnoRouterTesting`에서 시간·전환 ID를 제어하고, 시간 초과와 만료를 실제 대기 없이 검증할 수 있어야 한다. 기본 실행은 기존 실제 시간 동작을 유지한다. |
| FR6-040 | 테스트는 요청 시작·특정 생명주기 도달 대기·시간 진행·요청 취소·지연 승인·종료 결과 확인을 각각 제어한다. 서로 겹치는 요청도 실제 reducer·정책·스케줄러를 사용한다. |
| FR6-041 | 테스트 종료 시 미완료 요청·미해결 승인·대기 중 타이머를 식별한다. 정리 과정에서 테스트가 소유한 작업만 취소하고 정확히 한 번 종료한다. 임의 `sleep`이나 반복 `yield` 횟수로 준비 완료를 추측하지 않는다. |

### 3. 유효한 화면만 부분 복원

| ID | 요구사항 |
| --- | --- |
| FR6-042 | 디코딩·마이그레이션을 마친 상태에 대해 앱이 제공한 경로 유효성 판단으로 유지·제외·대체를 계획한다. 실패한 스택 위치부터 의존하는 후속 경로를 제거하고, 무관한 탭·기능·기존 창의 유효 영역은 보존한다. |
| FR6-043 | 복원 보고서는 유지·제외·대체한 위치와 구조적인 이유를 제공한다. 선택 항목이나 분할 화면 필수 열의 대체 규칙은 명시해야 하며, 유효한 대상이 없으면 앱이 지정한 대체 상태를 사용하거나 명시적으로 실패한다. |
| FR6-044 | 부분 복원도 한 번의 계획 적용으로 정상 정책을 통과해야 한다. 비동기 유효성 검사 중 취소·시간 초과·리비전 변경·정책 거절 시 복원에 의한 상태 변경은 없어야 하며, 동시 이동의 최신 결과를 보존한다. 손상된 데이터와 지원하지 않는 미래 버전은 부분 복원으로 우회하지 않는다. |

### 4. 매크로 경로 목록과 딥링크 진단

| ID | 요구사항 |
| --- | --- |
| FR6-045 | `@Router` 선언에서 경로 종류, 기능 이름공간, 딥링크 규칙, 매개변수 형태를 조회할 수 있어야 한다. 자식 모듈의 메타데이터도 부모에서 결합되며 실제 매칭 규칙과 불일치하지 않는다. |
| FR6-046 | URL 진단은 출처 검사·규칙 선택·매개변수 변환·준비 가능한 목표 상태와 차이를 설명한다. 기본 진단은 저장소·인증·정책·네트워크·앱 효과를 실행하지 않는다. 분석 불가능한 사용자 정의 resolver는 평가하지 않았음을 표시한다. |
| FR6-047 | Inspector는 경로 검색, URL 입력, 단계별 진단, 상태 변화 미리보기와 복사를 제공한다. 실제 이동 실행은 별도 명시적 동작이며 정상 정책을 통과한다. 내보내기는 경로 payload와 입력 URL의 민감 값을 기본적으로 숨긴다. |

### 5. 실제 이동 녹화와 회귀 테스트 생성

| ID | 요구사항 |
| --- | --- |
| FR6-048 | 앱이 명시적으로 시작한 녹화는 초기 상태, 모든 요청의 제출 순서·액션·맥락, 취소·지연 승인과 관찰 결과를 상한 안에서 수집한다. 실행 전에 거절되거나 합쳐진 요청도 누락하지 않는다. 녹화를 끄면 이러한 payload를 보관하지 않는다. |
| FR6-049 | 재현 자료는 버전·용량 제한·환경·필요한 앱 의존성 정보와 재현 가능 범위를 포함한다. 잘린 기록, 관찰 누락, 제어할 수 없는 앱 효과·외부 스케줄링은 불완전한 재현으로 표시하며 완전한 재현이라고 내보내지 않는다. |
| FR6-050 | 재현 자료로 실제 `RouterTestStore`를 사용하는 Swift Testing 테스트와 자료 파일을 생성한다. 관찰 결과와 개발자가 정한 기대 결과를 구분한다. 기대 결과나 의존성이 없으면 그 미완료 항목을 드러내며, 녹화된 실패 동작을 자동으로 정답 처리하지 않는다. |

### 6. 체크포인트와 뒤로·앞으로 이동

| ID | 요구사항 |
| --- | --- |
| FR6-051 | 앱은 선택적으로 상한 있는 이동 기록을 연결하고, 이름 있는 체크포인트를 만들며, 뒤로·앞으로·체크포인트 이동을 요청할 수 있어야 한다. 기록 대상은 경로·탭/분할 선택과 기존 장면 내부의 이동으로 명시한다. |
| FR6-052 | 이동 대상은 3단계의 검증·복원 규칙을 재사용해 현재 상태와 병합하고 정상 정책을 거친다. 성공하거나 목표 상태와 이미 같음이 확인된 경우에만 기록 위치를 이동한다. 거절·취소·오래된 대상은 상태와 기록 위치를 유지한다. |
| FR6-053 | 뒤로 간 뒤 새로운 이동이 성공하면 앞으로 기록을 제거하고, 거절된 요청은 기록하지 않는다. 중복 상태·기록 용량·영역 소멸·앱 세션 초기화 규칙을 제공한다. 과거 모달 완료 세션, 장면 생성/종료, 배지 및 업무 데이터를 되살리지 않는다. |

## 공통 제약

| ID | 제약 / 검증 |
| --- | --- |
| NFR6-001 | 기본 앱은 계속 `import InnoRouter` + `@Router` + 기존 host로 시작한다. 새 기능을 쓰지 않는 기존 매크로 소비자 예제를 그대로 컴파일한다. |
| NFR6-002 | `RouterStore`만 가변 이동 상태를 소유한다. 모든 실제 이동은 한 정책·취소·리비전 검증·커밋 경로를 사용한다. |
| NFR6-003 | 공개 제품은 `InnoRouter`, `InnoRouterTesting`, `InnoRouterInspector` 세 개를 유지한다. API 증가는 단계마다 의미와 심볼 차이를 검토한 후 기준선·예산을 함께 변경한다. |
| NFR6-004 | Swift 6.3+, iOS/iPadOS 18+, Mac Catalyst 18+, macOS 15+, tvOS 18+, watchOS 11+, visionOS 2+를 유지한다. 플랫폼별 기능 차이를 문서화하고 실제 실행 증거와 컴파일 증거를 구분한다. |
| NFR6-005 | 기록·시간 대기·경로 분석·이동 이력에는 명시적 상한과 종료 규칙이 있다. 소유자 해제와 취소 뒤 작업·객체가 남지 않는다. |
| NFR6-006 | 기본 Inspector 자료는 payload를 숨긴다. 원본 녹화·상세 표시·자료 내보내기는 별도 명시적 선택이며 자동 네트워크 전송은 없다. |
| NFR6-007 | Inspector 새 화면은 현지화 가능한 문구, 접근성 레이블, 키보드/포커스 탐색, 빈 상태·오류·취소 피드백을 제공한다. 네이티브 파일 선택이 없는 플랫폼은 API 기반 자료 처리를 제공하고 차이를 표시한다. |
| NFR6-008 | 테스트는 별도 라우팅 엔진을 만들지 않는다. 생성한 테스트 자료는 실행할 코드나 임의 closure를 담지 않으며 앱 의존성 공급자가 명시된 실제 production 경로를 검증한다. |
| NFR6-009 | 기존 85% 커버리지 기준, 포괄 커버리지 공개, 성능 예산, 타입 안전성, TSan/ASan 검증을 유지한다. 기존 예산을 새 기능 통과를 위해 자동 완화하지 않는다. |

## 실패·취소·부분 성공 계약

| 상황 | 동작 | 관련 요구사항 |
| --- | --- | --- |
| 자식 타입·영역 불일치 | 일부 경로를 조용히 필터링하지 않고 타입 오류 또는 구조화된 실패로 진단한다. 형제 상태는 보존한다. | FR6-037, FR6-038 |
| 테스트가 대기 준비 전에 시간을 진행 | 등록된 생명주기 장벽으로 동기화한다. 남은 대기는 `finish` 진단에 포함한다. | FR6-040, FR6-041 |
| 복원 검사 중 앱 상태 변경 | 캡처한 리비전과 다르면 적용을 거절한다. 재검사는 새로운 명시적 요청으로 수행한다. | FR6-044 |
