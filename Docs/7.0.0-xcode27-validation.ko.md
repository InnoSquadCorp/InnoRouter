## 발견 사항과 수정

1. Apple 소비자와 회귀 fixture의 throwing factory 호출, typed split/branch scope, 교체 후 만료된 feature authority 기대값을 현재 계약에 맞췄다. 새 scope를 얻는 정상 대조와 이전 scope 거절을 모두 유지했다. native scene fixture에는 명시적 window/immersive host descriptor를 추가했고, restoration worker 검사는 실제 child lifecycle을 기다리도록 했다.
2. 원본 후보는 Store에 alert/dialog 요청을 반영하지만 native renderer가 없었다. root alert, root dialog, nested child alert를 독립 UI 실패로 재현했다. UIKit/AppKit/WatchKit adapter를 추가했다. 원래 캡처한 runtime handle로 선택·닫힘을 제출하고, 거절/보류 뒤에는 native 종료 완료 후 새 attempt로 다시 표시한다. 기존 stack RouterHost 및 UIKit/AppKit bridge의 nonthrowing 계약은 유지했다.
3. 초기 UIKit 실험의 금지된 일반 alert presentation delegate 교체는 실제 assertion으로 발견해 제거했다. 지원되는 popover delegate만 사용한다. iPad 바깥쪽 탭이 선언 cancel의 값으로 완료되는 결함도 red UI로 보존하고 `.dismissed`로 수정했다. 명시적 cancel 버튼은 선언한 typed 값을 반환한다. run-loop turn 또는 Task.yield를 settlement 경계로 사용하지 않는다.
4. 생성된 scenario source가 throwing Store factory를 호출할 때 `try`를 누락해 독립 소비자가 컴파일되지 않았다. 생성기와 소비자를 수정하고 정상·의도된 실패 대조를 재실행했다.
5. 6.x API baseline을 7.0 후보의 의도된 표면으로 교체했다. API 예산은 실제 추출치 **1825 / 236 / 275**와 일치하며 여유 한도를 추가하지 않았다. 새 후보 Bool을 `isRevalidationRequired`로 정리하되 기존 저장키 `requiresRevalidation`은 유지했다. transient 문서 예제를 실제 compile fence로 만들었다.

## CI performance follow-up

초기 PR head의 원격 Xcode 27 전체 lane, lint, DocC, 문서, coverage, Inspector UI, Catalyst/watchOS, Thread Sanitizer, migration 및 exact-SHA 소비자는 통과했다. 원격 performance smoke는 snapshot preflight에서 보고서 생성 전에 실패했고, 같은 실패를 로컬 Xcode 27에서 재현했다. 기존 500-route fixture가 7.0의 provisional stack 한도 256을 초과한 것이 원인이었다.

Xcode 27 Release에서 7개 sample 모두 통과했으며 snapshot 중앙값은 780.45ms / 기존 한도 1,300ms였다. 이는 smoke 결과이며 앱 performance scorecard가 아니다. 원본 CI/로컬 실패와 수정 후 JSON report를 보존했다. 수정 head의 CI는 새로 실행하며 이전 head 성공으로 대체하지 않는다.
