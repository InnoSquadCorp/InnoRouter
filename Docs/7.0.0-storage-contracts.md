# 7.0 file-storage bounds and durability evidence

Verification narratives below were recovered from earlier work. They describe
historical scoped observations, not fresh evidence for this recovery commit.
See the recovery validation matrix for newly rerun exact-source results.

## Contract implemented

`RouterFileSnapshotStorage(fileURL:)` and
`RouterFilePendingLinkStorage(fileURL:)` now default to a finite 4 MiB
(4,194,304 bytes) limit for both loads and saves. Exactly the limit is accepted;
limit + 1 is rejected as `RouterSnapshotError.encodedDataTooLarge`. Rejection
does not truncate data or replace the previous file.

The 4 MiB value is the S06 measurement starting point, **not a calibrated release
default**. Representative consumer fixtures, adversarial peak-memory evidence,
and maintainer review are still required before release. Storage limits bound
encoded file bytes, not decoded graph/payload allocation or execution time.

Both adapters accept a positive override or an explicit unlimited opt-out:

```swift
let defaultStorage = RouterFileSnapshotStorage(fileURL: url)
let largerStorage = try RouterFileSnapshotStorage(
    fileURL: url, maximumByteCount: 8 * 1_024 * 1_024
)
let explicitlyUnlimited = try RouterFilePendingLinkStorage(
    fileURL: url, maximumByteCount: nil
)
```

Zero and negative overrides throw `RouterSnapshotError.invalidByteLimit` before
filesystem access. `nil` should be reserved for trusted input whose resource use
the app bounds elsewhere. Applications with existing files above 4 MiB must
explicitly choose an appropriate larger limit or migrate those files; the new
default preserves but rejects an oversized existing file.

Pending-link transport declarations moved into the Foundation-only
`RouterPendingLinkStorage.swift`. The public protocol and runtime module remain
unchanged. The driver itself was not moved or simulated.

## Read/write and ordering boundaries

- Read checks metadata before opening the bounded read, then reads chunks of at
  most 64 KiB, accumulating at most the configured limit and probing one overflow
  byte. A file that grows between metadata and reading is still rejected. The
  resulting error may report `limit + 1` as a lower bound instead of its full size
- A rejected save checks size before creating directories or writing. Accepted
  saves retain Foundation's `.atomic` file-replacement implementation
- `RouterDurabilityGate` preserves reservation order independently of task
  priority. A later remove revokes previously accepted saves which have not
  begun I/O. Automatic save invalidation preserves explicit save reservations
- `RouterByteStoreExecutor.save(_:ifCurrent:)` checks the gate at the actual
  synchronous storage boundary, including when work has already queued behind
  another operation. Abandoned or failed writes release their reservations
- An already-started synchronous app storage operation cannot be forcibly
  cancelled. Later removal waits for it and then removes its bytes. Atomic
  replacement is not a promise of power-loss recovery, fsync, or filesystem
  durability beyond the underlying adapter and OS

## Reproducible Linux gate

```sh
python3 scripts/run-storage-contracts.py --scratch /tmp/router-storage-debug \
  --warnings-as-errors
python3 scripts/run-storage-contracts.py --scratch /tmp/router-storage-release \
  --configuration release --warnings-as-errors
```

Use Swift 6.3 or newer; execution evidence here used Swift 6.4.0 on Linux. The
runner creates a dedicated test package and compiles byte-identical production
Core sources plus `RouterSnapshotStorage.swift`, `RouterPendingLinkStorage.swift`,
`RouterByteStore.swift`, and `RouterDurabilityGate.swift`. The same two test files
also belong to the root `InnoRouterTests` target through conditional imports.

The only source substitution is Core's unsupported-platform compilation guard:
it becomes a failing precondition if native capabilities are requested. No test
calls that path. There are no SwiftUI stubs, fake file stores, or OSLog shims.
`provenance.json` records toolchain, source/test hashes, exact substitution,
command, exit code, and whether those inputs still match the working tree.
`test.log` retains the complete execution output.

Coverage includes both adapters' missing and empty files, exact default and
explicit limits, limit + 1 reads/writes, invalid and unlimited settings,
metadata growth/shrink races, a sparse 1 GiB rejection before reading, Int.max
arithmetic, preservation of existing bytes, and concurrent complete-byte atomic
replacement. Gate/executor contracts cover reversed-priority acceptance,
save/remove/new-save ordering, queued cancellation versus explicit durability,
no stale resurrection, already-started writes, out-of-order abandoned
reservations, and queue progress after a rejected actual file write.

The two default-limit tests were executed before changing behavior. Both
compiled and failed for the intended reason: 4 MiB + 1 was accepted and replaced
the old file. Those are regression witnesses, not fixtures rejected by an
unrelated precondition.

This gate does **not** verify SwiftUI drivers, Apple filesystem behavior,
process-kill/power-loss recovery, the full package, native platforms, consumer
fixture calibration, or release readiness. Those gates remain separate.
