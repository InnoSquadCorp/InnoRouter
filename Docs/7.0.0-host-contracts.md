# 7.0 host contracts — implementation checkpoint

Status: development checkpoint, not a release or native-platform qualification.

## Implemented common boundary

- `RouterHostDescriptor<Route>` freezes root shapes and presentation/window/immersive catalogs. Shapes are explicit values, never inferred from restored candidates.
- `RouterStoreConfiguration.hostDescriptor` is optional for unhosted engine consumers. Native hosts require an explicit compatible descriptor.
- The Store validates complete candidates before scene callbacks/policies and again before commit. Rejection changes neither state nor descriptor.
- `replaceHost(with:descriptor:context:)` is an owner-only operation. It goes through ordinary resource, authorization, scheduling, policy, cancellation and deferral gates. It atomically publishes state, descriptor, structural generation and revision as one value.
- Accepted replacement retires previous scope/presentation authority, including equal states and reused persisted IDs. Ordinary path/selection/badge changes preserve unrelated scopes.
- Request generation fences survive queueing and deferred rebase. Snapshot/link worker entry points capture the same fence before asynchronous work.
- Tabs/custom containers can explicitly declare `.preserveDormant`. Contents remain in the graph and under structural/resource validation. Dormant branches cannot become selected renderers. Splits retain exact declared column roles; the state model does not support extra orphan columns.

## Native API checkpoint

`RouterTabHost` and split host supplied-state constructors throw on missing or incompatible contracts. Scoped view descriptors describe explicit stack/tab/split/custom children; their root/label closures receive same-Store scopes. No fabricated empty scope is used as error handling.

The existing nonthrowing `RouterHost(store:)` and UIKit/AppKit bridge signatures remain. The stack host exposes `validationFailure` and renders payload-safe recovery content. Its empty convenience uses a fixed safe stack descriptor without traps. Existing input-bearing throwing overloads validate their declared shape.

Default presentation catalogs explicitly declare stack children. Scene catalogs default to rejecting undeclared windows/immersive spaces; applications must supply the matching explicit scene declarations. A resolver must be pure and stable for a descriptor's lifetime. Arbitrary application callback work is not preemptible or measured as route payload bytes.

## Important incomplete boundaries

1. Shape equality alone does not bind a manual tab's root Route meaning. A frozen root-meaning contract and its native comparison are the next step. Do not claim that same-ID manual catalog remapping is already automatically detected. Explicit `replaceHost` does retire authority, but that alone is insufficient.
2. Native presentation rendering still requires recursive child renderer wiring. Portable enclosing completion/attempt contracts exist; the current stack surface still renders the presentation route only. Alert/dialog settlement ordering is not qualified.
3. SwiftUI SDK/typechecking, native interactions, scene lifecycle/platform behavior and complete public product/API/DocC gates remain unverified on Linux.

## Evidence at this checkpoint

- Swift 6.4 strict Core: 46 tests, including 21 new descriptor cases; 7 external public/private boundary probes.
- Actual Foundation/Observation Store engine: 516 tests/66 suites before adding the independent audit's four cases; the four cases also passed separately.
- Four staged negative controls demonstrate failures when scene-callback ordering, final-validation cancellation, host-generation fencing or same-ID lifetime retirement is disabled. Restored production code passes all 17 focused host tests.
- Native source parsing/formatting/lint and caller parsing were run. These are not native compilation or UI execution.
- Shared adapters retain explicit boundaries: Linux current-platform selection, logging-only shim, non-UI transaction assignment and reduced umbrella exports. No replacement Store or synthetic reducer is used.

Full Swift 6.3/6.4 Debug/Release matrices will be repeated after the remaining host/renderer work. Actual pilot data, scorecard rubric and performance acceptance inputs remain separate outstanding release gates.
