# 7.0 host contracts — implementation checkpoint

Status: development checkpoint, not a release or native-platform qualification.

## Implemented common boundary

- `RouterHostDescriptor<Route>` freezes root shapes, root meanings, and presentation/window/immersive catalogs. Shapes and meaning mappings are explicit values, never inferred from restored candidates.
- `RouterHostRootDeclaration<Route>` binds a relative branch path to an actual root Route value or an application-owned semantic declaration ID. Native renderer comparison checks the complete mapping; an omitted/empty mapping does not skip validation. Labels and localization are excluded.
- `RouterStoreConfiguration.hostDescriptor` is optional for unhosted engine consumers. Native hosts require an explicit compatible descriptor.
- The Store validates complete candidates before scene callbacks/policies and again before commit. Rejection changes neither state nor descriptor.
- `replaceHost(with:descriptor:context:)` is an owner-only operation. It goes through ordinary resource, authorization, scheduling, policy, cancellation and deferral gates. It atomically publishes state, descriptor, structural generation and revision as one value.
- Accepted replacement retires previous scope/presentation authority, including equal states and reused persisted IDs. Ordinary path/selection/badge changes preserve unrelated scopes.
- Request generation fences survive queueing and deferred rebase. Snapshot/link worker entry points capture the same fence before asynchronous work.
- Tabs/custom containers can explicitly declare `.preserveDormant`. Contents remain in the graph and under structural/resource validation. Dormant branches cannot become selected renderers. Splits retain exact declared column roles; the state model does not support extra orphan columns.

## Native API checkpoint

`RouterTabHost` and split host supplied-state constructors throw on missing or incompatible contracts. `RouterTabCatalog.hostDescriptor()` freezes its same-ID root Route mapping. Opaque split column closures require explicit semantic IDs, with matching `hostRootDeclarations` in an application-owned Store. Scoped view descriptors describe explicit stack/tab/split/custom children; their root/label closures receive same-Store scopes and `stack(declarationID:)` freezes root meaning. No fabricated empty scope is used as error handling.

The existing nonthrowing `RouterHost(store:)` and UIKit/AppKit bridge signatures remain. The stack host exposes `validationFailure` and renders payload-safe recovery content. Its empty convenience uses a fixed safe stack descriptor and `"router.root"` meaning without traps. Configured/supplied roots use the additive `rootDeclarationID` parameter, defaulting to `"router.root"`, and require that same root declaration in the Store. Existing input-bearing throwing overloads validate their complete declaration.

Default presentation catalogs explicitly declare stack children. Scene catalogs default to rejecting undeclared windows/immersive spaces; applications must supply the matching explicit scene declarations. A resolver must be pure and stable for a descriptor's lifetime. Arbitrary application callback work is not preemptible or measured as route payload bytes.

## Important incomplete boundaries

1. Root-meaning comparisons and native caller regression controls are implemented in source. Their native SwiftUI compilation and execution remain unverified here. Opaque closures rely on application-maintained semantic IDs; the library cannot infer changed implementation meaning from a reused ID.
2. Native presentation rendering now selects frozen stack/tab/split/custom renderers for canonical child nodes. Captured incarnation handles fence stale callbacks, and same-Store descendant authority retains the enclosing completion endpoint. Scene adapters validate fixed renderer declarations before rendering. These native paths have source coverage and syntax checks, but SwiftUI execution and alert/dialog settlement ordering are not qualified.
3. SwiftUI SDK/typechecking, native interactions, scene lifecycle/platform behavior and complete public product/API/DocC gates remain unverified on Linux.
