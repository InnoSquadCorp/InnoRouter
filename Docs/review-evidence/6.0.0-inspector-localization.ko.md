# Inspector 다국어·문서 검토

기준 커밋: `18f4ce6c1009b2949561bc54c800241200b849fd` 이후의 로컬 변경.
검토일: 2026-09-16. 이 기록은 새 변경분의 원격 CI 또는 정식 발행 증거가 아니다.

## 번역 검토

66개 원문과 15개 언어의 번역 990개를 실제 조작·상태와 대조해 직접 작성하고
읽어 확인했다. 번역 생성이나 단어 일괄 치환에 스크립트를 사용하지 않았다.
언어별 원어민 검수까지 받았다는 뜻은 아니다.

- 시나리오 `recording`을 화면·음성 녹화와 구분했다. 한국어의 `녹화`를 `기록`으로
  고치고, 중국어 `录制/錄製` 대신 `记录/記錄`, 스페인어·포르투갈어에서도
  이벤트 기록 의미의 `registro`를 사용했다.
- Stop은 결과 보존, Cancel은 원본 데이터 폐기이며 이미 적용된 navigation을
  되돌리지 않는다. 각 언어의 두 조작을 구분했다.
- complete/incomplete는 캡처 완전성, failed는 명령 실패, recording은 진행 중이다.
  deferred/rejected/unresolved도 보류·거절·경로 해석 실패로 구분했다.
- raw fixture 경고는 데이터가 익명화됐다고 약속하지 않는다. 경로에 연결된 값이
  포함될 수 있다는 의미를 유지하고 기본 비식별 진단 번들과 구분했다.
- 사용하지 않는 예전 제목과 `Share URL` 키를 제거했다. 실제 공유는 입력 URL이
  아니라 구조 분석이므로 `Share analysis`가 맞다.
- 각 원문에 기능 의미를 설명하는 translator comment를 추가했다.

## 코드와 문서

- `String(localized:bundle:locale:)`에 locale만 전달해도 프로세스 언어와 다른
  `.lproj`가 선택된다고 가정할 수 없었다. 명시적 한국어 테스트로 실패를 확인한
  뒤 package 언어 번들을 직접 선택하도록 수정했다.
- 영어 `.lproj`가 생성되지 않는 경우에도 영어 source key로 대체한다.
  한국어 번들이 영어 요청에 잘못 선택되는 반례도 테스트로 확인·수정했다.
- SwiftUI locale을 각 Inspector view에서 읽고, 기존 failure/status를 표시할 때
  다시 번역한다. 타임라인 시각도 같은 locale의 형식을 사용한다.
- diagnostic identifier, JSON, 앱이 제공한 문자열은 그대로 보존한다.
- RTL/LTR 전환 후 네이티브 split/list의 위치와 터치 영역이 어긋나거나 글자가
  거울처럼 남는 현상을 실제 화면으로 확인했다. `.balanced`만으로는 18.5 문제를
  해결하지 못했고, 27에서 조작이 통과해도 시각적 반전은 남았다.
- 방향이 바뀔 때 네이티브 컨테이너만 새로 만들도록 했다. 외부의 안정된 경계는
  암묵적인 부모 TabView의 선택을 유지하고, timeline/selection/filter/comparison과
  recorder/scenario는 재생성 경계 밖에 둔다. locale만 바꿀 때는 재생성하지 않는다.
- 새 왕복 테스트의 스크린샷에서 Deep-link Form도 Arabic→English 뒤 글자가
  뒤집히는 것을 확인했다. Form만 안정된 외부 컨테이너 안에서 다시 만들고,
  URL/filter/executionTask/status 및 사라질 때의 취소 동작은 바깥에 유지했다.
  실행 중 전환도 임의 취소나 추가 제출 없이 유지되는지 새 checkpoint로 검증했다.
- README 두 언어, Inspector DocC, 기여 지침, changelog와
  [다국어 안내](../inspector-localization.md)를 맞췄다. 영문 README의 fixture v5를
  실제 v7로 바로잡고 이후 버전 불일치가 문서 검사에서 실패하도록 했다.

## 로컬 자동 검증

- `localization-coverage.log`: 4 tests 통과. 지역별 6 cases, 전체 990개 컴파일
  번역값, 영어/미지원 언어 fallback, 반복 locale 변경을 검증했다.
- `localization-principle.log`: package 620 tests, DocC, 공개 API, 문서, 예제,
  외부 소비자 7 tests, generated scenario, source lint, 전체 Apple 플랫폼의
  compile/interface gate 통과. iOS와 iPadOS는 같은 generic compile destination이다.
- 타임라인 방향 경계 보완 뒤 `localization-principle-final.log`의 전체 gate가
  통과했다. 이후 Deep-link Form 보완분은 별도 최종 로그로 구분한다.
- 최종 Form 보완과 실행 중 언어 전환 테스트까지 포함한 소스에서
  `localization-principle-complete.log`가 `All checks passed`로 종료했다.
  package 620 tests, DocC, 공개 API, 문서, 외부 소비자와 generated scenario,
  source lint 및 iOS 18/Catalyst 18/macOS 15/tvOS 18/watchOS 11/visionOS 2의
  빌드·공개 인터페이스 검증을 모두 통과했다.
- `localization-package-final.log`, `localization-docc-final.log`,
  `localization-docs-final.log`, `localization-lint-final.log`: 분할 화면 배치 수정
  후 package 620 tests와 문서·린트를 다시 실행해 통과했다.
- 기존 pending-work 진단을 확인하는 expected known issue 1건은 그대로다.
  Xcode 27의 생성 resource accessor scoped-import 경고와 `exit code 0` compiler
  진단은 전체 플랫폼 로그에 보존했다. 경고 없는 빌드라고 표현하지 않는다.

로그와 결과 번들은 저장소의 `.build/release600/` 아래에 보존한다.
검증 스크립트는 읽기 전용 구조 검사이며 번역을 생성·수정하지 않는다.

## UI 증거 채택 기준

영어·한국어·독일어·아랍어를 같은 Inspector에서 전환하고, URL 실행/취소 및
기록 시작/중지/취소를 실제로 조작한다. Arabic→English→Arabic 전환에서 입력 URL,
기존 실행 결과, 선택한 상세 이벤트와 진행 중인 기록을 유지해야 한다.
스크린샷을 직접 확인하여 글자 반전과 잘림도 검사한다.

최종 소스에는 새 테스트명
`testInspectorMountedLocaleBidirectionalStatePreservation`을 사용한다.
추가 assertion을 넣었는데도 이전 메서드명과 checkpoint만 실행된 결과는 성공하더라도
최종 증거로 채택하지 않는다. 새 DerivedData에서 빌드하고 이 테스트 및 새 checkpoint가
실제 실행 로그에 존재하는지를 확인한다. 테스트 조건·시간 제한을 완화하지 않는다.
CI도 `check-inspector-ui-results.py`로 현재 두 테스트의 실제 이름과 Passed 결과를
검사한다. 과거 2 PASS 번들을 거절하는 음성 대조군을 확인했다.

## 최종 시뮬레이터 결과

- iPadOS 18.5: `inspector-localization-ipad-proof.xcresult`.
- iPadOS 27.0: `inspector-localization-ipad27-proof.xcresult`.
- 각 결과에서 현재 UI 테스트 2개가 통과했다. 합계 4 PASS, 실패·skip·expected
  failure 0이며 xcresult의 runtimeWarnings도 비어 있다. 검증 스크립트로 실제
  테스트 이름까지 다시 확인했다.
- 실행 중 English→Arabic 전환은 실행 버튼 비활성/취소 가능 상태와 policy 제출
  횟수 4를 유지했다. 언어 변경이 실행 취소나 추가 제출을 일으키지 않았다.
- Arabic→English→Arabic 왕복은 URL, 실행 결과, 선택한 상세 이벤트 및 진행 중인
  기록을 보존했다. 같은 뷰에서 영어·한국어·독일어·아랍어의 실행/취소와 기록
  시작/중지/취소를 조작했다.
- 각 OS의 47개 checkpoint(다국어 37개와 기존 회귀 10개)에 screenshot과
  accessibility hierarchy를 보존했다. 중간 `fresh` 번들은 Form 반전 문제가
  남아 있었으므로 최종 성공 근거에서 제외했다.
- 최종 screenshot을 직접 열어 두 OS의 영어 Form 왕복에서 문자 반전이 없어졌고,
  독일어의 긴 기록 버튼이 잘리거나 겹치지 않으며, 아랍어 RTL에서 선택과 기록
  상태가 유지되는 것을 확인했다. 자동 assertion 성공만으로 시각 검증을 대신하지
  않았다.

이 결과는 두 iPad 시뮬레이터에서 네 언어를 확인한 범위다. 16개 언어 전체의
모든 플랫폼 UI 검증이나 실기기 접근성 검증으로 확대 해석하지 않는다.
