## 수정 전 확정 반례

| ID | 수정 전 결과 | 수정 후 계약 |
| --- | --- | --- |
| R6R7-F01 | 복원 정책 gate가 열린 채 `stop()`해도 실행 lane이 점유되어 무관한 요청이 busy로 거절됨 | activation별 transition ID를 취소해 gate 해제 전 terminal과 lane 해제를 보장 |
| R6R7-F02 | history 제출 전에 창이 존재하는 정상 기록을 전체 state equality로 잘못 거절 | navigation projection은 intent로, 당시 scene을 포함한 prepared action은 provenance로 별도 검증 |
| R6R7-F03 | history 재개 action만 변조한 자료가 생성·재생됨 | 시간순 producer 상태에서 준비한 action과 다르면 production 요청 전에 거절 |
| R6R7-F04 | 원본 stop/reset을 잃은 자료가 revision을 만든 뒤 state mismatch | format 4로 표현되지 않은 history 수명 종료를 구체적 preflight 오류로 거절 |

수정 전 독립 probe는 각 반례를 3회 동일하게 재현했다. probe의 exit 0은 진단 프로그램 종료일 뿐
제품 통과 판정이 아니며, 완료 근거는 아래 저장소 영구 테스트다.

## 구현 결과

### 복원 취소 소유권

- `RouterStateRestoration`이 activation별 transition ID를 요청 전에 예약하고 활성 ID를 보관한다.
- `stop()`과 activation task 취소는 `RouterStore.cancelRequest(_:)`로 그 요청의 정책 race만 끝낸다.
- ID가 같은 activation의 `defer`만 handle을 정리하므로 이전 activation의 늦은 cleanup이 새 activation을 지우지 않는다.
- 기존 generation/precondition 검사는 load/decode 뒤의 늦은 commit을 계속 차단한다.

### history provenance와 수명 preflight

- `RouterScenarioHistoryValidator`가 fixture의 시간순 관찰 상태를 순수하게 투영한다.
- 최초 history action은 제출 시점 상태에 `RouterHistory.prepareNavigationMerge`를 적용한 값과 일치해야 한다.
- rebase 재개는 이전 producer가 실제 준비한 action을 보관해 반복 deferral에도 같은 규칙을 적용한다.
- history `allow`가 cancelled/rejected terminal을 주장하면 format 4에 stop/reset 수명이 표현되지 않은 것으로 보고
  `unsupportedHistoryLifetime(step:)`을 generator와 runner에서 첫 production 요청 전에 반환한다.
- 일반 exact-state 계획과 history navigation-only 의미, production 정책·commit 경로는 변경하지 않았다.

## 재리뷰 결론과 남은 경계

- 네 수정 전 반례는 각각 저장소 회귀로 고정되었고 정상 자료·변조 자료·표현 불가능한 수명을 분리한다.
- 취소는 소유 transition만 대상으로 하며 serialize 큐와 새 activation, 무관한 요청을 보존한다.
- history 검증은 replay 전용 상태 적용이나 기대값 자기승인을 추가하지 않고 production merge 함수를 공유한다.
- 공개 fixture format은 4를 유지한다. 새 공개 API는 구체적 수명 오류 case 두 개뿐이며 기준선·예산에 반영했다.
- 현재 520행의 dirty status에는 사용자의 기존 6.0 변경이 함께 있다. 이를 정리·되돌리거나 전체 staging하지 않았다.

아래는 이번 로컬 완료 주장에 포함하지 않은 외부 release gate다.

| 외부 gate | 상태 |
| --- | --- |
| 실제 native UI와 기기 상호작용 | 미실행 |
| Swift 6.3 고정 toolchain | 미실행 — 현재 검증은 Swift 6.4 |
| 실제 채택 앱의 exact-SHA consumer 검증 | 미실행 |
| 원격 CI, 태그, registry, 서명·배포 | 미실행, 별도 승인 필요 |
| 유지관리자 최종 코드 리뷰·승인 | 미기록 |

따라서 판정은 **일곱 번째 계획의 로컬 구현·자동 검증 완료**다. 외부 gate와 승인 전에는
**6.0.0 배포 준비 완료 또는 배포 완료**로 승격하지 않는다. 커밋·푸시·태그·배포는 이번 범위에 포함하지 않았다.
