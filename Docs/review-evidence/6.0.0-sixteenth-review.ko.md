# InnoRouter 6.0.0 — 16차 개선 로컬 검증

검증일: 2026-09-13 KST

## 판정

16차 계획의 F01~F04와 Q01~Q02를 수정했고, 현재 체크아웃에서 실행 가능한 인수 기준은 모두 통과했다. 상태는 **로컬 구현·검증 완료**다. 커밋·푸시·정확한 SHA의 원격 CI·태그·릴리스는 수행하지 않았으므로 배포 완료나 원격 release candidate로 판정하지 않는다.

## 구현과 green 증거

### History와 waiter

- `RouterHistory`가 요청 실행 전 active ownership을 보유하고, 최초 deferred 이벤트를 관찰하는 순간 active→pending으로 이전한다.
- `RouterHistory+Move`의 await 반환 경로는 terminal 이벤트에서 이미 소비된 ownership을 되살리지 않는다. 원래 요청 결과는 거짓 cancellation로 바꾸지 않는다.
- 16차 suite의 queued immediate resume/cancel은 Store/History 잔여 ownership 0, revision·cursor·entry 정합성을 함께 검증한다.
- record waiter는 package 전용 등록 callback을 통해 continuation 저장 완료를 먼저 확인한다. restore 전 entry count 1, restore 후 entry count 2와 waiter의 true 완료를 검증한다.

### 공유 restoration 수명

- `RouterRestorationDriver`가 초기 activation Task와 waiter를 소유한다. 호출자 cancellation은 자기 waiter/manual claim만 정리하고 다른 attachment/manual owner의 observation을 중단하지 않는다.
- 마지막 owner 해제와 명시적 `stop()`만 공유 activation·restore request family·observer·예약 save를 정리한다. 취소된 최초 시도는 재활성화 시 복원을 다시 시도한다.
- package attach 경합뿐 아니라 실제 `NSHostingView` 두 개를 window에 mount해 첫 root 제거 뒤 attachment 1, observer 1, 후속 snapshot save를 검증했다.
- 기존 driver 교체 native-host 테스트의 100회 `Task.yield()` 추측은 2초 한도의 조건 기반 수명 대기로 변경했다. 첫 TSan 실행에서 느린 계측 환경 때문에 이 테스트가 한 번 실패했고, 보강 뒤 focused test와 TSan 전체 재실행이 통과했다. 데이터 레이스 보고는 두 실행 모두 없었다.

### macro-first feature catalog

- 매크로는 직접 선언된 static/class `routerFeatureCatalog`와 parameterless enum case를 실제 충돌로 진단한다. 같은 이름의 instance 속성은 허용한다.
- 조건부 clause 내부를 무조건 활성이라고 재귀 판정하지 않는다. flag-off 소비자는 generated metadata를 실제 사용하며 성공하고, flag-on 실제 static 충돌은 Swift compiler의 `invalid redeclaration`로 실패한다.
- 직접 case 충돌은 macro E067 fixture로 실패한다. 기존 conditional `@FeatureRoute` E065 및 availability-negative 소비자 실패도 유지했다.
- behavior test와 외부 consumer가 instance 값과 생성 `ExternalFeatureRoute.routerFeatureCatalog`를 동시에 소비한다.

## 남은 배포 게이트

- 이 Mac에는 `/Applications/Xcode.app` 하나만 있고 현재 Swift는 6.4다. `test-check-platform-interface.sh`가 Xcode 26.6/27의 flag dialect fixture를 검증했지만, 정확한 pinned Xcode 26.6 / Swift 6.3.3 compiler로 이 미커밋 patch를 실제 빌드한 증거는 아니다.
- visionOS compile/interface는 통과했으나 실제 headset/simulator에서 immersive open/dismiss 상호작용을 수행한 결과는 아니다.
- 실제 채택 앱의 migration/build/runtime, 접근성/VoiceOver, 정확한 commit SHA의 원격 CI, tag/release는 별도 승인·환경이 필요하다.

따라서 이번 결과는 16차 계획의 코드 수정과 로컬 품질 게이트를 닫지만, 그 자체로 6.0.0 배포 승인을 대신하지 않는다.

## 2026-09-14 후속 정정 — 18차 재검토

위 명령·수치·당시 PASS는 역사적 실행 증거로 유지한다. 이후 activation 예약/반환 수명, 동일 ID deferral timer 재사용, 연관값 catalog case, 부모 route의 `Self` payload 문맥에서 추가 반례가 발견되어 16차의 포괄적 완료 판정 범위를 다시 열었다.

후속 제품 수정과 새 후보의 548개 테스트·consumer/compiler·sanitizer·coverage·성능 결과는 [18차 계획](../6.0.0-eighteenth-review-remediation-plan.ko.md) 및 [18차 검토 증거](6.0.0-eighteenth-review.ko.md)를 따른다. 이 정정은 과거 로그를 무효화하지 않고, 그 로그만으로 후속 반례까지 해결됐다고 해석하지 않도록 범위를 제한한다.
