## 발견 사항

### R6R14-F01 / P2 — activate 호출 취소 후 보류 요청이 남음

위치: `Sources/InnoRouterSwiftUI/RouterStateRestoration.swift:238-247`.

복원 정책의 deferred 이벤트 직후 activate 호출 Task를 취소하면 CancellationError를 받고 driver는 inactive가 된다. 하지만 catch가 request root를 취소하지 않고 식별자만 지운다. 보류 요청은 계속 Store에 남으며 driver.stop()에서도 더는 해당 family를 찾을 수 없다. 최대 보류 수 1에서 다음 별도 요청이 deferralCapacityExceeded로 거절됨을 재현했다.

재현: `Tests/InnoRouterTests/Review14RuntimeProbes.swift`의 `activationCancellationAtDeferralReleasesCapacity`.
수정 방향: 같은 activation generation의 종료 처리가 family 취소 → ownership 해제 순서를 공유하도록 한다. 새 activation의 작업은 취소하면 안 된다.

### R6R14-F02 / P2 — 오래된 immersive 복구가 열린 native 공간을 남김

위치: `Sources/InnoRouterSwiftUI/RouterSceneLifecycle.swift:119-126`.

사용자 닫기 거절/보류 후 재열기가 진행 중일 때 canonical state에서 공간이 닫히고, 이후 open이 .opened로 끝나는 순서를 재현했다. 복구 helper는 false를 반환하고 ticket만 해제하며 성공한 오래된 native open에 대한 반대 효과를 실행할 통로가 없다. Store는 nil이지만 open 효과는 남는다. RouterSceneDriver의 별도 재조정 큐는 이 lifecycle helper의 open과 공유되지 않는다.

재현: `Tests/InnoRouterTests/Review14SceneProbes.swift`의 `obsoleteImmersiveRestoreClosesSuccessfulNativeOpen`.
수정 방향: 복구 open과 dismiss의 소유권/직렬화를 통합하고, 더는 canonical하지 않은 성공 결과는 정리한다. onAppear가 ticket을 정상 해제한 경우와 진짜 lifetime 교체를 구분하고, replacement 공간을 잘못 닫지 않는 회귀 테스트가 필요하다.

### R6R14-F03 / P2 — 부분 재조정 실패가 정상 창을 닫았다 다시 엶

위치: `Sources/InnoRouterSwiftUI/RouterSceneDriver.swift:249-276`.

Store에는 A·B 창이 있고 명시적 manual catalog에는 A만 있는 허용된 입력을 사용했다. A를 열고 B를 unsupported로 rollback하면 함수가 previousStoreIdentity 갱신 전에 반환한다. 다음 revision에서 A까지 다른 소유자의 창으로 인식하여 dismiss/open을 다시 수행한다. A의 openedWindow 2회, dismissedWindow 1회를 확인했다. 창 내 비라우터 UI 상태 손실이나 중복 lifecycle 효과 위험이 있다.

재현: `Tests/InnoRouterTests/Review14SceneProbes.swift`의 `incompleteReconciliationDoesNotReopenUnaffectedWindow`.
수정 방향: 이미 실행한 native 효과의 store/lifetime identity도 부분 진행 상태와 함께 기록한다. 기존 same-ID replacement/store replacement 동작은 유지한다.

### R6R14-F04 / P2 — 같은 Store의 다른 History 이동을 무시함

위치: `Sources/InnoRouterSwiftUI/RouterHistory.swift:399-403`.

같은 Store에 History 두 개를 연결하고 A→B로 이동한 다음 첫 History에서 뒤로 간다. 둘째 History는 모든 source=.history commit을 무시하므로 여전히 A→B를 currentEntry로 보여 준다. 둘째에서 뒤로 가면 completed(.unchanged)로 끝나며 실제 화면은 A에 머문다. 공개 API에 다중 연결 제한이나 오류도 없다.

재현: `Tests/InnoRouterTests/Review14RuntimeProbes.swift`의 `secondHistoryTracksFirstHistoryNavigation`.
수정 방향: 자기 자신이 소유한 이동만 자기 기록에서 제외하고 다른 History의 이동을 동기화하거나, 하나만 연결할 수 있다는 제약을 API에서 명시적으로 강제한다.

### R6R14-F05 / P2 — CasePath 바인딩의 자동 이름과 사용자 label 충돌

위치: `Sources/InnoRouterMacrosPlugin/CasePathEnumIteration.swift:132-140`.

유효한 `case mixed(Int, v0: String)`에서 생성되는 extract 패턴은 `mixed(let v0, let v0)`이다. 실제 `Cases.mixed` 참조 시 invalid redeclaration 및 (Int, Int)→(Int, String) 변환 오류로 컴파일이 실패한다. @CasePathable에서 재현했으며 @Routable도 같은 생성기를 사용한다.

재현: `macro-probes.swift`, `PROBE_COLLISION`.
수정 방향: source label과 독립된 충돌 없는 내부 바인딩을 생성한다. 혼합 label, escaped label, 반복 label과 다중 payload 소비자 테스트가 필요하다.

### R6R14-F06 / P2 — 조건부 @available 속성 유실

위치: `Sources/InnoRouterMacrosPlugin/CasePathEnumIteration.swift:153-160`.

`#if os(macOS)` 안에 @available(macOS 26, *) 속성만 두고 그 뒤에 nullary case를 선언하면, enum 자체는 macOS 15 target에서 유효하다. 매크로는 AttributeSyntax만 수집하므로 조건부 속성을 버린다. 생성된 Cases.future가 availability 없이 .future를 참조하여 컴파일 실패한다. 직접 붙인 @available 대조군은 통과한다.

재현: `macro-probes.swift`, `PROBE_AVAILABILITY`.
수정 방향: conditional attribute 구조를 보존한다. 속성 조건부와 case 선언 조건부를 별도 regression matrix로 둔다.

### R6R14-F07 / P2 — 재귀 payload의 Self가 중첩 Cases로 재해석됨

위치: `Sources/InnoRouterMacrosPlugin/CasePathEnumIteration.swift:111-115`, `CasePathMemberGeneration.swift:29-31`.

유효한 `indirect enum SelfPayload { case end; case next(Self) }`의 payload type 문자열을 중첩 Cases 안에 그대로 삽입한다. 생성되는 `CasePath<SelfPayload, Self>`에서 Self가 SelfPayload.Cases가 되어 embed/extract 양쪽의 타입이 맞지 않는다. `Cases.next` 소비자 컴파일이 실패하고, payload를 원래 enum 이름으로 명시한 대조군은 통과한다.

재현: `macro-probes.swift`, `PROBE_SELF`.
수정 방향: type syntax에서 선언 문맥의 Self를 보존/정규화한다. Self, Self?, [Self] 등의 중첩 표현도 확인한다.

### R6R14-F08 / P3 — 시나리오 생성기가 단독 _ 식별자를 허용

위치: `Sources/InnoRouterTesting/RouterScenarioSourceGeneration.swift:209-217`.

testName="_" 및 storeFactory="_" 입력을 오류 없이 받아들인다. 결과의 `func _()` 또는 `_()`는 Swift 컴파일러가 거절한다. 선언 이름이나 qualified name의 각 요소는 단독 underscore를 거절해야 한다.

재현: `Tests/InnoRouterTestingTests/Review14GeneratorProbes.swift` 및 `discard-identifier.swift`의 compiler 진단.
수정 방향: 단독 _를 모든 식별자 위치에서 거절하고 `_name`은 정상 허용하는 대조 테스트를 추가한다.
