## 2. 계획 작성 중 추가 검증

아래는 이번 계획 작성 과정에서 새로 실행한 결과다. 독립 영역 2개는 F08/F09로 추가했고,
기존 원인의 확장 반례는 F05/F06/F07에 포함했다.

| 항목 | probe / 경계 | 실제 결과 / 양성 대조 |
| --- | --- | --- |
| F08 | `replacementRestorationDriver` — 같은 mounted modifier의 driver A→B | root generation 1 렌더 확인 후 A `.active`, B `.inactive`. 이전 activation은 저장 executor 순서와 분리해 완료시킴 |
| F09 | `replacementSceneStoreSameRevision` — empty A rev0→window B rev0 | open effect 0. 같은 B에 추가 push로 revision만 올리면 `.openedWindow(second)` 발생하는 양성 대조 통과 |
| F09 | `coalescedWindowReplacement` — 같은 Store에서 window first 닫기→같은 UUID second 열기, 중간 render 없음 | canonical route는 second인데 trace는 initial `.openedWindow(first)`뿐. first dismiss와 second open 누락 |
| F05 확장 | `staticRouteCollision` — product("settings")와 literal settings | `/products/settings`가 product가 아닌 `.settings`로 해석. 빈 값만 막으면 해결되지 않음 |
| F07 확장 | `resolverValidationParity` — factory `bad factory` | `generateFiles`는 typed error로 거절(양성 대조), `generate`는 오류 없이 source 반환 |
| F06 확장 | `conditional-presentation-string.swift` — #if의 문자열에만 `@PresentationResult` | 실제 annotation이 없어도 E055 컴파일 오류. raw-text 검색의 오탐 |

추가 Swift Testing probe는 5개 테스트 함수가 모두 실패했다. 이 중 F09에는 두 함수가 있고,
F05/F07은 기존 항목의 확장이다. 문자열 오탐 compiler 반례는 별도로 실패했다.

추가 명령:

```bash

swiftc -typecheck -swift-version 6 -target arm64-apple-macos15.0 \
  -I .build/out/Products/Debug \
  -load-plugin-executable .build/out/Products/Debug/InnoRouterMacrosPlugin#InnoRouterMacrosPlugin \
  /tmp/innorouter-review-20260911.D6kz8O/conditional-presentation-string.swift
```

Artifacts:

- `/tmp/innorouter-review-20260911.D6kz8O/repo/Tests/InnoRouterTests/ReviewDriverProbes.swift`
- `/tmp/innorouter-review-20260911.D6kz8O/conditional-presentation-string.swift`

직전 검토의 `qualified-presentation.swift/.log`도 확인했다. `#if` 내부
`@InnoRouterMacros.PresentationResult`는 E055 대신 생성 `Presentation` member 누락으로 실패했다.
이번에는 이 compiler 명령을 재실행하지 않았으므로 새 실행 수에 포함하지 않는다.

## 4. 구현 후 추적

기준 revision `92bded1d343f0feb39e949ddc6a8e1ad4b844cfd` 위의 로컬 작업 트리에서
T00~T09와 C01~C24를 완료했다. 아래 결과는 발행 직전 source에 대한 로컬 인수 기록이며,
T10의 pinned toolchain·실제 native 상호작용·원격 후보·승인·발행을 대신하지 않는다.

### 4.1 수정 결과

| 항목 | 구현 및 영구 회귀 |
| --- | --- |
| F01 | `RouterHost`, `RouterTabHost`, 2/3열 `RouterSplitHost`에서 내부 생성 Store만 `@State`로 소유하고 외부 입력은 현재 Store를 따른다. AppKit mounted Host 및 Tab/Split A→B 교체 회귀를 추가했다. |
| F02 | window restoration 요청을 `(sceneID, lifecycleToken)`에 결합하고 queue/policy/deferral/commit 전 수명 precondition을 유지한다. 같은 UUID로 교체된 새 창은 이전 disappearance 요청으로 닫히지 않는다. |
| F03 | History가 validation부터 반복 deferral까지 request root를 소유한다. `stop`, `reset`, deinit 및 호출자 Task 취소가 active task와 Store family를 정리하고 `.cancelled`를 반환한다. 비협조 policy의 늦은 결과도 state/cursor/report를 바꾸지 않는다. |
| F04/F08 | restoration driver가 활성 restore root/deferral과 attachment lease를 추적한다. modifier A→B는 A를 먼저 detach하고 B를 attach하며, 이전 View의 늦은 disappearance가 현재 B를 중단하지 않는다. 마지막 lease와 수동 activation의 수명을 구분한다. |
| F05 | builder가 빈 필수 path를 거절하고 생성 macro의 standalone/feature URL은 실제 resolver로 동일 route round-trip이 확인될 때만 반환한다. literal/dynamic 충돌과 feature 모호성은 `nil`이다. |
| F06 | CasePath case 수집/생성이 `#if/#elseif/#else`와 중첩 구조를 보존한다. PresentationResult 조건 검사는 `AttributeSyntax`를 사용해 qualified marker를 잡고 문자열 오탐을 제거했다. 사용자 `-D`, `os`, `arch`, `canImport` 실제 소비자 fixture를 추가했다. |
| F07 | `generate`/`generateFiles`가 공통 identifier/factory 검증을 사용하며 함수명은 단일 Swift identifier만 허용한다. feature resolver factory 검증 차이를 제거했다. |
| F09 | SceneDriver task identity에 Store identity와 revision을 함께 사용하고 native 비교 상태를 Store·scene route·lifetime에 결합했다. 같은 revision Store 교체, same-ID route 교체, sibling revision 무관 재오픈 방지를 검증했다. |

계획 실행 중 추가로 발견한 History 호출자 취소 누수, terminal restoration deferral의 root 잔류,
modifier 교체 후 이전 disappearance 경쟁도 같은 소유권 모델로 수정하고 회귀에 포함했다.
발행 전 재검토에서는 활성 복원이 policy 안에서 대기하는 동안 무관한 `.restoration` 요청이 busy로 거절될 때 root 소유권을 잘못 해제할 수 있는 event 상관관계 반례를 추가로 재현했다. 초기 transition ID 또는 실제 resumed deferral ID가 일치할 때만 active root를 정리하도록 수정했다.
마지막 코드 리뷰에서는 취소된 visionOS reconciliation의 늦은 immersive open 성공이 cache/event를 오염시키는 경로를 추가로 차단했다. 결과 반영 전 Store identity·revision을 재검증하고 stale 성공은 native dismiss로 정리하며, 변경 뒤 visionOS 전체 build/interface gate를 다시 통과했다.
`RouterHistory`의 공개 타입은 동작을 바꾸지 않고 `RouterHistoryTypes.swift`로 분리해 파일 길이와 타입 책임 예산을 회복했다.
공개 변경은 `RouterHistoryFailure.cancelled` 추가 1건이며 migration 영향은 exhaustive switch에 새 case 처리가 필요하다는 점이다.

- 외부 macro-first 소비자: 7개 runtime 테스트 통과. 추가로 `INNOROUTER_CUSTOM_CONDITIONAL`을 전달한 실제 compiler build에서 `#elseif`와 중첩 `canImport`/`arch` CasePath를 확인했다.
