## 2026-09-11 정정 — 열한 번째 재검토

열 번째 표의 통과 로그 자체는 보존하지만, 아래 행의 완료 범위는 후속 반례 때문에 축소한다.
새 결함과 수정 후 근거는 [열한 번째 회귀·증거 추적표](6.0.0-eleventh-review.ko.md)에 기록한다.

| 이전 판정 | 정정 내용 |
| --- | --- |
| R6R10-C13 통과 | 단일 owned deferral 취소만으로 반복 D1→D2→D3 lineage를 증명하지 못했다. 반복 deferral과 재개 중 비협조 policy를 열한 번째 검증에서 다시 연다. |
| R6R10-C18 통과 | registry/ticket 정합성은 통과했지만 실제 modifier의 immersive open `error`/`userCancelled` 결과와 같은 ID의 새 lifetime에 도착하는 늦은 결과는 검증하지 못했다. |
| R6R10-C21~22 통과 | sibling/window 보존과 strict revision은 통과했지만 Feature owner 자체가 교체된 뒤 rebase하는 반례와 nested ancestor 교체는 빠져 있었다. |
| R6R10-C23 통과 | 당시 fixture는 scoped intent를 기록했으나 typed Feature resolver와 ownership precondition을 별도 프로세스 replay에 복원하지 못했다. |
| R6R10-C24 통과 | macro-first 소비자 빌드는 통과했지만 conditional `@FeatureRoute` compiler 진단과 `@PresentationResult` availability 호출 경계는 검증 범위가 아니었다. |

따라서 열 번째 문서의 “C20~24 통과”와 광범위한 로컬 완료 요약은 위 제한을 전제로만 읽어야 한다.
실제 native window/immersive 조작, 정확한 Xcode 26.6·Swift 6.3.3, 후보 SHA 원격 CI 및 발행은 계속 미검증이다.

현재 작업 트리는 로컬 구현 후보이며 commit/push/tag/release는 수행하지 않았다. 따라서 “코드 수정과 로컬 검증 완료”와
“배포 가능/발행 완료”를 동일하게 취급하지 않는다.
