## 수정 전 관찰

최종 독립 probe를 3회 실행한 결과(매회 UUID만 다름):

```text
HISTORY_REPLAY failed=stateMismatch(step: 4) windows=0
INVALID_RESOLVE generated=true
INVALID_RESOLVE replaySucceeded=2 claimsPushHome=true actualRoot=...detail...
RESTORATION_RESTART second=observationResumed status=active
RESTORATION_OLD_FAILED status=failed("firstLoad")
RESTORATION_PROBE expectedAlreadyActive=true actual=noSnapshot
```

| ID | 실제 반례 / 원인 | 수정 후 필수 증명 |
| --- | --- | --- |
| R6R6-F01 | activate의 load 대기→stop→새 activate→이전 load 실패. 이전 catch가 새 observationTask를 취소한다. | 새 수명 status/lastActivation/관찰 보존, 후속 commit 실제 저장, 이전 요청 추가 commit 0 |
| R6R6-F02 | history back 보류→새 창→rebase. 원본은 창 1개, 완전한 5-step fixture의 replay는 창 0개와 mismatch. preparation closure의 의미가 fixture에 없다. | 같은 정책의 독립 재생 및 생성 consumer에서 창·navigation·revision delta·terminal 일치 |
| R6R6-F03 | resumed step 제출 index=-999, action=push(home), context=기본값으로 변조. 생성·재생 성공, 실제 실행은 push(detail). | 단일/조합 변조가 첫 production 요청 전 구조 오류, 모든 새 부작용 0 |
| R6R6-F04 | 병렬 두 테스트의 static parseCount reset/증가/조회 경합. 전체 suite assertion 실패와 TSan race 확인. | 기본 병렬 suite 및 해당 회귀를 포함한 TSan에서 실패/경쟁 0, resolver 호출 assertion 유지 |
| R6R6-V01 | R6R5 완료 행 일부가 실제 Binding 조합/consumer assertion과 대응하지 않음. 실제 Binding 호출은 root sheet 교체 테스트 1개. | 과거 모든 필수 행→실제 assertion 매핑, 누락 자동 회귀 추가, UI 미실행 분리 |
