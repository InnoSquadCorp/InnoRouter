`6896791786afcf97ae9c5d1043aafdc1c506010c`. The local investigation and

`D8C14585-925C-43A9-8FA2-BD80F2B1BB24` repaired lifetime

## Two deterministic contracts

The original id-only diagnostic is preserved byte-for-byte at
`fixtures/ImmersiveLateAppearanceContractTests.swift`, SHA256
`dfafb6d65026e6b516f2fc59960a5d62bf735dbb86ee33de80c33fd6fde3e728`.
It remains outside package targets because its after-repair assertions are
intentionally red. Before repair it passes; after committed repair it reports
three issues. The legacy `appearanceAfterCommittedRepair` test instead treats
nil canonical state and rejecting old/nil lifetimes as success.

The approved bound-value contract retains the removal commit, then requires a
new recovery commit and fresh scope. It never rewinds revision or revives an
expired scope. Copy `Tests/InnoRouterTests/ImmersiveAttributedContractTests.swift`
to an isolated baseline checkout and run:

```sh
swift test --jobs 2 --no-parallel -Xswiftc -DROUTER_BASELINE_CONTRACT \
  --filter ImmersiveAttributedContractTests
```

At the baseline, before passes and after fails four assertions: canonical
scene, final revision, commit list, and current scope. With this change both
orders pass with the same assertions: before has revision 1; after observes
repair 2 and recovery 3, commits [1,2,3], expired old scope, and valid new
scope. Unrelated root navigation survives and duplicate callbacks commit
nothing. Continuations and request observations fix event order; no sleep,
retry, or yield count advances the scenario.

## Local verification

The completed investigation recorded 1,392 SwiftPM test methods passing,
31 native ordered executions passing, normal native allow/reject/cancel
passing individually, three real-scene fault executions passing, and the
official platform suite passing 13 methods/14 parameter executions with
exit 0 and a complete xcresult. Publication reran SwiftPM, all 31 ordered
executions, and the actual native probes after replacing the diagnostic
environment closure with a stable model reference and separating native
adoption, dismissal, open, and repair-precondition helpers to satisfy the
unchanged source responsibility budgets. Fresh publication results and CI
state are recorded in the PR description.

The native ordered harness renders the same assertion expressions as
throwing checks in a visionOS app. Its 31 cases inject native results/events;
they do not reproduce OS failure. Controls include no-appearance error and
user cancellation, task cancellation before/after start and during recovery,
authorization/generation revocation, disappearance during authorization,
explicit close, new lifetime/Store/request, driver replacement, same-owner
reentry, retained navigation plans, immediate post-recovery close, and
originating deferral allow/reject/cancel/rebase with stale-request controls.

The actual native normal probes retain the original PASS conditions and
20-second failure timeout. Their OS restoration results were opened.
`--injected-restoration` opens a real scene and captures its real SwiftUI
bound value, converts OS opened to a library error, and gates library
admission until repair commits. Physical appearance occurred before repair
in those executions. The gate does not delay failure with a timer or add an
open. This validates transport, physical presence, driver adoption and close
effects, separately from the helper's after-repair event ordering.

Each actual probe recorded two opens/two appearances, with the restoration
request UUID matching the second native bound value. Fault mode observed
native-present/canonical-absent at revision 2, recovered the same native
attempt at revision 3 without another open, and allowed close at revision 4.
Reject/cancel retained both states before explicit cleanup.

## Public boundary and limitations

The only added public surface is the visionOS Scene wrapper and its
`id:store:rendering:presentations:` initializer/body. The payload, observer,
ledger, recovery and deferral continuity stay internal. The downstream
visionOS smoke route deliberately has no Codable conformance. Host symbol
baselines/budgets are unchanged because they exclude this conditional
surface; the visionOS emitted-interface gate checks it separately.

True OS error followed by late physical appearance was not reproduced on the
installed runtime, and Xcode 26.6 was not verified. This includes native
convergence timing under that error. No claim of original-CI resolution or
7.0.0 release readiness follows from the local passes. Nil, foreign, expired,
cancelled or replaced activation values acquire no recovery authority.
Existing id-only scenes retain fail-closed behavior. Wrapper IDs must remain
stable in the scene graph; conditional declaration removal is not modeled.

The completed platform xcresult has a pre-existing SceneStorage runtime
warning in RouterDeepLinkHandling. The SwiftPM suite has one expected
`withKnownIssue` deferral diagnostic. Neither is reported as zero-warning
validation or a new failure.
