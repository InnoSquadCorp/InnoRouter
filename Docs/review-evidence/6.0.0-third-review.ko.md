# InnoRouter 6.0.0 세 번째 리뷰 수정 증거

## 범위와 기준

- 기준 브랜치/HEAD: `main` / `1ca15fa8dc814017b55881e2895a5c6907b7c921`
- 구현 시작 시 작업 트리: 변경 513개, 미추적 121개. 기존 6.0 마이그레이션
  작업을 보존하고 R6R3 수정 파일만 추가로 변경했다.
- 실행 환경: Xcode 27.0 (`27A5252f`), Apple Swift 6.4
  (`swiftlang-6.4.0.33.1`), arm64 macOS.
- 수정 전 전체 369개 논리 테스트 통과 기록은 새 반례를 발견하기 전의 기준선이며,
  아래 수정의 통과 증거로 재사용하지 않는다.
- 릴리스 기준 Xcode 26.6 / Swift 6.3, 원격 CI, 실제 채택 앱과 실제 Inspector
  UI 조작은 이 로컬 실행의 검증 범위가 아니다.

## 구현 결과

- 스케줄러가 큐에서 승격한 executor Task를 명시적으로 소유하고 취소·종료 시 해제한다.
- typed presentation 값 예약은 transition/deferral 소유자를 가지며, commit한 dismissal의
  소유자가 같을 때만 `.value`를 전달한다. 다른 전환으로 제거되면 `.dismissed`가 된다.
- scenario replay는 시작 상태를 preflight하고, 실패/취소 시 자신이 만든 request와 실제
  deferral ID만 취소·회수한다. 생성 테스트도 throw 경로에서 test store를 정리한다.
- Inspector scenario controller는 임의 `Error.description`을 사용자 요약에 넣지 않고
  `startFailed`, `stopFailed`, `importFailed`의 구조화된 실패만 노출한다.
- macro catalog의 변환 순수성은 문자열 철자가 아니라 runtime metatype identity로 결정한다.
- feature-aware URL renderer는 전역 부모 allowlist를 case 전체에 적용하지 않고 선언 소유
  route에 origin 검사를 위임한다.

## 실행 증거

- `swift test --jobs 2`: 378개 논리 테스트 통과. `finish()`가 정리 전 pending work를
  진단하는 의도된 known issue 1건은 유지했다.
- 포커스 runtime/Testing/Inspector/macro behavior 회귀와 독립 `ConsumerSmoke` 6개
  테스트: 통과.
- `scripts/principle-gates.sh --platforms=all`: package, 세 DocC catalog, 공개 API와
  symbol budget, 문서/코드 조각, example·생성 scenario·독립 소비자, source gate,
  fail-fast 및 전 플랫폼 build/interface를 포함해 전체 통과.
- `scripts/generated-scenario-smoke.sh`: 별도 생성 package의 정상 fixture 통과 및
  초기 상태/state/revision/terminal 음성 fixture 실패 확인.
- iOS 18/iPadOS 18, Mac Catalyst 18, macOS 15, tvOS 18, watchOS 11,
  visionOS 2에서 macro-first와 developer-tools consumer를 검증했다. iPadOS는 iOS와
  같은 generic iOS Simulator destination을 사용하므로 중복 build를 생략했다.
- Thread Sanitizer 대상 94개와 Address Sanitizer 대상 90개 논리 테스트가 통과했고
  sanitizer 진단은 0건이었다.
- portable coverage 85.55%(`12,362/14,450`), comprehensive coverage
  78.76%(`14,239/18,078`). 85% 하한과 제외 범위는 완화하지 않았다.
- release-mode 성능 7축이 모두 기존 상한 안에서 통과했다. 중앙값은 reducer 62.72 ms,
  snapshot 167.19 ms, deep link 187.94 ms, Inspector export 2,775.49 ms,
  scenario capture 50.67 ms, history 24.74 ms, catalog 511.61 ms다.
- SwiftFormat, strict SwiftLint, source 책임·privacy/API gate, 문서 일치, README/DocC
  코드, shell 문법과 `git diff --check`: 통과.
- Xcode 27/Swift 6.4의 library-evolution 검증에서 SwiftPM 생성
  `resource_bundle_accessor.swift`의 scoped-import 미지원 경고가 출력됐지만 각 build와
  공개 인터페이스 검증은 성공했다. 프로젝트가 직접 작성한 소스 경고는 아니다.

## 미검증 경계

- 이 증거는 로컬 Swift 6.4 결과다. Xcode 26.6 / Swift 6.3 고정 결과와 원격 CI는 별도다.
- 실제 iOS/iPadOS/tvOS/watchOS/visionOS Inspector 조작과 VoiceOver·키보드·포커스는
  시뮬레이터/기기 증거가 없어 완료로 판정하지 않는다.
- 커밋, push, tag, GitHub Release 또는 registry 배포는 수행하지 않았다.

## 최종 재리뷰 결론

- R6R3-F01~07은 구현과 독립 반례 회귀로 해결됐다.
- 최종 정적 재리뷰에서 일반 Inspector archive 오류의 원문 표시 1건을 추가 발견해
  제거했고, Inspector 모듈의 임의 `Error.description`/`localizedDescription` 표시를
  금지하는 source gate를 추가했다.
- 남은 항목은 코드 결함이 아니라 고정 Swift 6.3 원격 실행, 실제 Inspector UI 접근성
  조작, 실제 채택 앱, 유지관리자 승인과 배포 절차다.
