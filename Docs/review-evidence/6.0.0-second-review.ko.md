# InnoRouter 6.0.0 두 번째 재검토 증거

기준일은 2026-09-05, 기준 HEAD는
`1ca15fa8dc814017b55881e2895a5c6907b7c921`이며 기존 6.0 미커밋 작업 트리를 포함한다.
도구 모음은 Xcode 27.0 / Apple Swift 6.4였다. 이 문서는 `/tmp` 진단이 사라져도
반례와 정규 회귀의 연결을 보존하기 위한 기록이며, 현재 작업의 커밋·푸시·배포 증거가 아니다.

| ID | 입력 순서와 수정 전 반례 | 정상 계약 | 정규 회귀 |
| --- | --- | --- | --- |
| A01 | 부모 교체 정책 대기 → feature 타입 모달 enqueue → 교체 commit → 모달이 sibling에 commit | projection 실패, 추가 revision 0 | `queuedTypedFeaturePresentationRejectsBeforeMutation` |
| A02 | custom `DeepLinkParameterValue` URL preview 1회 → converter 2회 | 기본 preview converter 0회 | `customParameterConversionIsNotEvaluated` |
| A03 | history back → 정책 보류 2회 → 승인 2회 → store/cursor 불일치 | 최종 commit에서 cursor 1회 이동 | `historySurvivesSecondDeferral` |
| A04 | checkpoint route를 validator가 대체 → 복원 직후 entry는 과거 값 | entry/checkpoint가 최종 projection과 일치 | `checkpointReflectsValidatedReplacement` |
| A05 | 매 실행 새 deferral UUID → 캡처 UUID로 새 store를 승인 | 논리 ID를 새 outcome ID에 매핑 | `deferralDecisionControl` |
| A06 | A/B 제출 → B 결과 회수 → A 결과 지연 회수 | 각 outcome의 자체 state/revision 검증 | `delayedAwaitUsesItsOwnCompletedOutcome` |
| A07 | 삭제 route → fallback → replacement → replacement 미검증 | 모든 대체 체인 재검증, cycle/상한 실패 | `fallbackReplacementMustBeValidated`, `replacementCycleFailsClosed` |
| A08 | recorder/history waiter 시작 → Task 취소 → stop 전까지 미종료 | 취소만으로 false 반환 | `cancelledCaptureWaitersComplete`, `cancelledHistoryWaitersComplete` |
| A09 | 미해결 deferral → `finish` | pending 진단 후 owner 작업·deferral 0 | `finishClearsOwnedDeferrals` |
| A10 | 공유 clock에서 A만 timer 등록 → B barrier 호출 | B는 완료되지 않고 취소로 false | `ownTimerBarrierDoesNotUseOtherStore` |
| A11 | recorder stop → time/resolve control 호출 | fixture 불변, clock/store 불변 | `stoppedCaptureDoesNotAcceptNewControls` |
| A12 | child deep-link catalog + parent feature | namespace가 붙은 parent catalog와 matcher 정합 | `parentCatalogIncludesChildFeatureEntries`, `ambiguousFeatureCatalogFailsClosed` |
| G01 | 환경/의존성 없는 v2 fixture, base64 단일 소스 | v3 metadata preflight, 별도 JSON과 Swift 파일 | `replayPreflightIsSideEffectFree`, `generated-scenario-smoke.sh` |
| G02 | URL 원문 기본 공유, 문자열 실행 상태, 녹화 UI 없음 | payload-free 기본 공유, 구조화 상태, 명시적 raw export | `deepLinkAnalysis`, `inspectorScenarioAdapterFlow` |
| G03 | 기존 4개 workload와 분리된 구성요소 테스트만 존재 | 3개 통합 흐름과 신규 3개 성능 축 | 통합 회귀와 7-sample performance gate |

원래 독립 진단의 제어 사례는 정상 macro-first 소비자 컴파일이었다. 정규 회귀는 실패를
skip하거나 영구 known issue로 숨기지 않는다. `finishClearsOwnedDeferrals`의
`withKnownIssue`는 의도된 pending 진단 자체를 확인하고, 그 뒤 cleanup 결과는 별도 assertion으로
검증한다. A10의 30ms는 준비 추측이 아니라 무한 대기를 막는 음성 watchdog으로만 사용한다.
