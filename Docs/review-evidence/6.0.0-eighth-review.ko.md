## 수정 전 확인한 반례

| 결함 | 재현과 실제 결과 | 수정 후 요구 결과 |
| --- | --- | --- |
| R6R8-F01 | 빈 pending slot restore의 load 중 driver.cancel 또는 복원 Task.cancel → load 해제 뒤 slotRestored=true, status=active | 늦은 복원의 slot 변경·성공 0. 성공한 cancel 뒤 저장소와 새 작업의 값 보존 |
| R6R8-F02 | push(home/detail) → gate에서 push(modal) 대기 → history.goBack 큐 진입 → 앞 요청 commit. 원본 staleState/revision 3, 재생은 revision 4 commit 뒤 stateMismatch(step: 3) | 원본 preparation revision을 보존해 같은 거절과 revision 재현 |
| R6R8-F03 | 일반 action deferral → resolve(allow) 다음 정책에서 Task.cancel. 원본 revision 1, complete=true/cancelControls=0. 재생은 gate 해제 뒤 revision 2 commit | 실제 취소 제어를 기록하고 gate 미해제 상태에서 cancelled/revision 1 재현 |
| R6R8-F04 | history resume 중 Task.cancel, 동일 자료에 실제 cancel control을 명시해도 generator/runner가 unsupportedHistoryLifetime(step: 3) | 명시적 취소는 재생하고 수명 정보 누락만 구체적으로 사전 거절 |

F03 대조군은 실제 cancel control만 추가하면 같은 정책에서 정상 재생했다.
F04는 이 대조군을 history로 바꿨을 때도 여전히 거절되어, 녹화 누락과 독립된 분류 결함임을 확인했다.

## 필수 회귀 행 — 설계 식별자, 실제 함수명 아님
