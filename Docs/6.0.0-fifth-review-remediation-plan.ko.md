기존 FR/AC는 재번호화하지 않는다. 이 기술 계획은 기존 요구 동작을 보완하는

아래 인수 기준은 무엇이 참이어야 하는지를, 단계별 구현안은 어떻게 달성할지를 구분한다.
계획 작성 요청은 코드 수정·커밋·푸시·태그·배포 승인이 아니다.

## 사실, 전제와 범위

### 확인한 사실

- 직전 리뷰의 4건이 별도 실행 프로그램에서 3회 동일하게 재현됐다.
  이번 계획 작성에서는 보존된 실행 로그와 현재 관련 소스를 대조했다.
- 직전 리뷰의 388개 테스트, public API 기준선(1148 / 207 / 215), 문서 정합성 검사는
  통과했다. 테스트의 intentional known issue 1건은 별도다. 이 수치는 이번 계획 작성에서
  다시 실행한 결과가 아니며, 새 반례의 안전성을 증명하지 않는다.
- native 모달 반례는 실제 Binding 구현에 테스트 접근 helper만 추가한 임시 컴파일
  단위를 실행한 결과다. 실제 OS 제스처를 실행한 결과는 아니다.
- 현재 history는 보류 전에 계산한 전체 `RouterPlan`을 재개하며, replay는 완료된
  handle 제거 후 같은 논리 request ID의 제출을 다시 허용한다.

### 유지할 전제 / 비목표

- macro-first, 하나의 `RouterStore`, 세 공개 제품, Swift 6.3+와 현재 OS floor를 유지한다.
  iOS 17 하향, 5.x 호환층 복구, 신규 기능 추가, 별도 라우팅 엔진은 범위 밖이다.
- 필요한 6.0 breaking change는 검토할 수 있지만 기본안은 내부 실행·소유권 보완이다.
  새 필수 앱 설정이나 공개 우회 API를 만들지 않는다.
- 취소는 라이브러리가 소유한 실행·대기·보류를 종료해야 한다. 취소를 무시하는 앱 정책의
  임의 외부 효과를 강제 중단하거나 이미 완료된 정상 commit을 rollback한다고 약속하지 않는다.
- 일반 `RouterPlan`의 exact-state 의미를 바꾸지 않는다. history만 navigation-only
  병합 계약을 유지해야 한다. 잘못된 replay fixture를 조용히 보정하거나 중복을 무시하지 않는다.
- 사용자 변경은 보존한다. 공개 API/fixture 형식 변경이 필요해지면 영향과 대안을 먼저 기록한다.

### 외부 검증 경계

Swift 6.3 고정 환경/원격 CI, 실제 채택 앱, 플랫폼별 native UI는 독립 증거가 필요하다.
담당은 유지관리자와 후속 구현 작업자다. 환경 미확보 시 미실행으로 남기며 자동 검증 통과와
분리한다. 로컬 수정 완료와 배포 승인은 같은 상태가 아니다.

## 순차 실행 원칙

**T00 → T01 → T02 → T03 → T04 → T05** 순서로 진행한다.
T01에서 취소 소유권을 먼저 닫고, T02에서 같은 실행 경계를 사용하는 native callback을
보호한다. T03은 일반 plan과 history의 의미를 분리하고, T04는 재현 도구의 신뢰성을 보강한다.

각 단계는 실패 assertion 작성 → 현재 구현의 실패 확인 → 수정 → 정상/경합 회귀 →
변경 코드 재리뷰 → 증거 기록 순서다. 다음 단계로 넘어가기 전에 해당 단계의 필수 회귀를 통과한다.
동기화는 요청 관찰·큐 등록·정책 진입·terminal 장벽과 기존 가상 clock을 사용한다.
임의 sleep/yield 횟수, skip/known issue 추가, assertion 삭제, coverage 제외 확대,
성능 예산 완화로 통과시키지 않는다. watchdog은 hang 검출용이며 readiness 증거가 아니다.

- [x] 각 변형에 실제 테스트명, 수정 전 실패, 수정 후 결과, 환경, 관련 AC 칸을 만든다.

## R6R5-T01 — presentation의 전체 요청 수명에 취소 전파

변경 접점: `RouterStore+Presentation`, `RouterStore+Deferral`, `RouterStore+Policy`,
`RouterStore+Scheduling`, 필요한 내부 request metadata.

- [x] presentation UUID와 원본/재개 transition ID, deferral의 소유 관계를 연결한다.
  `takeDeferredRequest`부터 새 executor 등록 사이에도 취소 소유권이 끊기지 않아야 한다.
- [x] 취소 시 기존 scheduler 취소 경로를 통해 실제 queued/active 실행과 policy race를
  종료한다. waiter 존재 여부만 확인하는 commit guard를 취소 전파의 대체물로 사용하지 않는다.
- [x] 취소가 executor 등록 전에 도착하면 새 실행이 시작되지 않게 한다. 정책 복귀와 새
  defer 등록 전에도 request precondition을 확인하여 이미 취소된 요청이 재보류되지 않게 한다.
- [x] 원본·재개·재보류의 종료에서 연결 정보를 회수한다. 한 요청의 취소로 다른 모달,
  같은 store의 다른 요청 또는 별도 store를 취소하지 않는다.
- [x] 정상 typed 결과, 이미 표시된 모달의 취소 dismissal, 정책 거절/만료의 계약을 유지한다.

필수 회귀:

- [x] resume queued, active policy, executor 등록 전 취소를 각각 검사한다.
- [x] 정책을 풀기 전에 resume terminal·소유 pending 정리·다음 요청 진행을 확인한다.
  이후 테스트 gate를 풀어 늦은 allow/defer가 commit/보류를 만들지 않는지 확인한다.
- [x] FIFO와 rejectWhileBusy, timeout 있음/없음, 반복 보류, 중복 취소를 검증한다.
- [x] 무관한 요청은 정상 완료하고 각 terminal/typed 결과는 정확히 한 번 전달된다.

완료 조건: R6R5-AC01. 외부 정책의 수동 release가 라이브러리 실행 종료의 선행 조건이 아니어야 한다.

## R6R5-T02 — native 모달 callback을 원래 표시 수명에 결합

변경 접점: `RouterStoreStackSurface`, scope의 내부 전달 helper, 기존 presentation identity precondition.

- [x] Binding을 원래 표시된 presentation의 scope·UUID에 결합한다. callback이 도착한
  순간의 최신 UUID를 읽어 대상을 바꾸지 않는다. 화면 재평가 후 늦게 온 callback도 포함한다.
- [x] native dismissal은 `.system` 맥락과 정상 policy 경로를 유지하고 큐 실행·정책 복귀·
  보류 재개·commit 경계에서 원래 대상을 검증한다. stale 요청은 새 모달을 수정하지 않는다.
- [x] sheet/cover/popover의 지원 플랫폼 및 스타일 adaptation 분기를 같은 보호에 연결한다.
- [x] 인접한 detent setter도 같은 늦은 callback 위험을 실제 회귀로 확인한다. 재현되면
  같은 identity 보호를 적용한다. 전역 revision 검사로 정상적인 무관한 변경까지 막지 않는다.

필수 회귀:

- [x] A→B 교체 대기 중 nil setter, 교체 후 늦은 setter, 같은 route/새 UUID, 중복 nil,
  보류 후 교체·재개를 검사한다. root·중첩 scope·서로 다른 window를 포함한다.
- [x] B의 상태뿐 아니라 typed waiter가 정상 finish로 값을 받는지 확인한다.
- [x] 정상 A dismissal, 정책 거절 후 canonical/native 재조정, system provenance를 확인한다.
- [ ] iOS Simulator와 macOS native host에서 실제 닫기·교체를 검증한다.
  실행 환경이 없으면 자동 Binding 검증과 분리하여 미실행으로 기록한다.

완료 조건: R6R5-AC02. 실제 제품 Binding 경로가 보호되어야 하며 helper 단독 통과로 종결하지 않는다.

2026-09-06 R6R6 정정: v1.0 당시 자동 근거는 root sheet 교체 중심이어서 위 일부 완료 표시가
필수 조합보다 넓었다. 여섯 번째 리뷰에서 root/nested/window, style adaptation, 중복 nil,
보류·교체, typed waiter, detent, 정책 거절 및 정상 system dismissal을 실제 제품 Binding
helper 경로의 별도 회귀로 보강했다. 실제 iOS/macOS native 제스처 행은 계속 미실행이다.

## R6R5-T03 — history 재개 시 navigation-only 목표 재구성

변경 접점: `RouterHistory`, `RouterHistory+State`, 내부 요청 준비/보류 재개 경계.

- [x] 기본 구현안은 history 요청이 이동 이력 entry와 generation을 유지하고, 실행·재개
  시점의 현재 상태로 `merge`를 다시 수행하도록 내부 목표 구성 단계를 두는 것이다.
  일반 앱의 `.apply(RouterPlan)`은 계속 exact-state 요청이다.
- [x] 새로 구성한 목표를 reduce/정책 실행 전에 확정한다. 정책이 검토한 candidate와
  commit 대상을 동일하게 유지한다. await 이후 상태 변경은 기존 revision 검증으로 거절한다.
- [x] 새 창·공간·배지는 보존하고 사라진 장면은 재생성하지 않는다. 활성 presentation과
  경로 변경이 충돌하거나 topology가 호환되지 않으면 구조화된 실패로 종료한다.
- [x] 기존 validator와 generation/reset/stop 계약을 유지한다. 재검증이 필요한 비동기
  경계는 기존 취소·revision 검사와 연결하고, 정책 승인 뒤 목표를 몰래 바꾸지 않는다.
- [x] 반복 보류에서도 cursor를 성공/unchanged에만 한 번 갱신한다. 거절·취소·오래된
  세션의 결과로 state나 cursor가 바뀌지 않게 한다.

필수 회귀:

- [x] 원본 반례(보류 후 창+충돌 모달 추가)는 재개 실패, state/cursor 불변이어야 한다.
- [x] 보류 후 창만 추가, 배지 변경, 비충돌 모달 변경은 현재 수명을 보존한 안전한 이동을 검증한다.
- [x] 창 삭제·공간 교체·nested topology 변경·반복 보류·reset/stop·취소를 검사한다.
- [x] `.requireUnchangedState`의 stale 거절, 일반 exact plan, 정상 back/forward/checkpoint를 유지한다.

완료 조건: R6R5-AC03. 모든 rebase를 일괄 거절하거나 새 모달을 지워서 성공시키지 않는다.
내부 목표 구성만으로 해결할 수 없어 공개 action/fixture 형식 변경이 필요하면 영향 검토를 먼저 요청한다.

## R6R5-T04 — replay control graph의 실행 전 검증

변경 접점: `RouterScenarioReplay`, `RouterScenarioFixture`, `RouterScenarioSourceGeneration`, capture 대조군.

- [x] 시작하지 않음 → 시작됨 → 종료됨의 논리 요청 이력을 검증한다. 시작 control은
  submit 또는 resolveDeferral 중 정확히 하나이고, terminal은 정확히 한 번이어야 한다.
- [x] 중복/누락/알 수 없는 request ID, 재사용된 종료 ID, 중복 terminal, 제출·종료
  eventIndex와 step 불일치를 첫 production 요청 전에 거절한다.
- [x] deferral 생산과 소비의 순서·소유 관계를 검증한다. 정상 resume은 별도 transition ID를

## 완료 보고와 다음 단계

보고는 **코드 수정**, **로컬 자동 검증**, **native/CI/실제 소비자 검증**, **배포 조건**을
