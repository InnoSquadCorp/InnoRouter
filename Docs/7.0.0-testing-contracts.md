# Testing contracts on a non-Apple executor

Verification narratives below were recovered from earlier work. They describe
historical scoped observations, not fresh evidence for this recovery commit.
See the recovery validation matrix for newly rerun exact-source results.

## Execution boundary

`scripts/run-testing-contracts.py` stages the actual Core, DeepLink, non-UI
Store, Inspector, and complete Testing sources. Every Testing test source is
copied without import or implementation replacements. The harness records
source/test hashes, each test function's name and source line, toolchain,
command, configuration, exit code, and post-run source parity. Previous source
snapshots, logs, and provenance are archived before a scratch is reused.

The explicitly reduced `InnoRouter` module re-exports Core, DeepLink, and the
non-UI Store target. It omits Macros and System. The unused Apple capability
guard traps instead of returning invented capabilities, and OSLog is a no-op.
There is no fake SwiftUI, Store, Inspector, or Testing implementation.

This is not validation of the shipped umbrella, product graph, native callbacks,
SwiftUI rendering, Apple logging/localization, Swift 6.3 minimum, or release
readiness. Corelibs copies the real localization catalog; SwiftPM's warning
about its native `.xcstrings` processing rule is an excluded Apple resource
boundary, not evidence that native resource compilation passed.

```sh
python3 scripts/run-testing-contracts.py \
  --scratch /tmp/router-testing-contracts --jobs 1 --warnings-as-errors
python3 scripts/run-testing-contracts.py \
  --scratch /tmp/router-testing-contracts --configuration release \
  --jobs 1 --warnings-as-errors
```

Run these serially. The default whole-run limit is 300 seconds and interrupted
or timed-out runs fail explicitly. A zero-test run or an unfiltered cohort that
differs from the recorded function inventory also fails.

## Scenario format 8

Captured state and actions cannot reconstruct runtime ownership, application
authorization, or callback closures. `RouterScenarioStep.replayLimitation`
records a stable, payload-free limitation code. It never stores an incarnation,
authority token, authorization result, or callback closure. Known codes cover
ownership replacement, execution preconditions, and runtime authorization.
Unknown codes round-trip and fail closed too.

Format 8 requires the field even when it is null. Format 7 is rejected rather
than silently interpreting missing ownership metadata as replayable. Adding
developer expectations preserves the limitation. Both source generation APIs
and replay reject unsupported steps with a typed error before executing any
request against the target Store.

Captured feature plans/callbacks retain their observations and declarative
metadata but do not claim full ownership replay. Explicitly authored feature
scenarios still validate resolver requirements and execute their declared
recipe. The generated-scenario smoke's feature fixture is authored, not a
captured runtime callback; its Apple product-graph execution remains separate.

An already expired feature projection can reject before Store submission. Its
unmatched rejection leaves capture incomplete; no fictitious submitted request
is added merely to make replay possible.

## Observed results and controls

The expanded suite contains 81 functions across seven suites: 62 pre-existing
functions, six limitation contracts, one authored feature resolver control, and
12 import-boundary contracts. The expanded 81-function suite passes Swift 6.4/Linux Debug and Release; each
run is recorded separately by source hash. The one `withKnownIssue` is an intentional positive check that
`RouterTestStore.finish()` diagnoses outstanding work, not an accepted product
failure. Test totals are not technical scores or performance samples.

The initial compilation identified obsolete `[RouterScopeID]` test literals;
these were migrated to explicit `.branch` components. Release also exposed an
immediate cancellation-flag assertion that assumed policy-task exit preceded
request completion. The fixture now waits for an explicit, cancellation-safe
observation barrier under its test time limit. Failed and interrupted attempts
are retained rather than replaced by successful reruns.

External-import probes confirm valid public configuration/draft/unknown-code
usage compiles while state/Store mutation, private replay metadata, private
authorization callbacks, and the package-only policy-bypass entry point remain
inaccessible. These probe staged real modules; they do not validate package
product discovery or native umbrella exports.

## Bounded serialized fixture import

`RouterScenarioFixture.decode(from:)` now invokes the shared iterative JSON
preflight before Foundation decodes the fixture or application route payloads.
It checks the complete document, including unknown fields, for syntax, UTF-8,
duplicate keys (including escaped aliases), depth, and token count. The shared
parser also counts the required top-level steps array before any route decoder
runs; nested arrays with the same key do not contribute to that count.

Provisional defaults are 2 MiB encoded bytes, 2,000 steps, depth 64, and 131,072
JSON tokens. Existing nonpositive-limit normalization to one is preserved.
Explicit positive overrides are supported, including Int.max without arithmetic
overflow. All bounds apply independently; raising the step ceiling does not
waive byte or complexity limits. These defaults are not calibrated release
recommendations.

Twelve focused contracts cover exact boundaries and limit-plus-one failures,
escaped keys, unknown nested fields, missing/non-array steps, duplicate keys,
truncation, invalid UTF-8, normalized limits, and decoder-call instrumentation.
Rejected input remains byte-identical and never enters an application route
decoder; valid controls confirm that the same decoder actually executes.

A repeatable prior-body control borrows the exact Fixture.decode method body
from a chosen revision while retaining the current parameter/schema declarations
so the new boundary tests compile:

```sh
python3 scripts/run-testing-contracts.py \
  --scratch /tmp/router-testing-contracts --jobs 1 --warnings-as-errors \
  --fixture-decoder-body-revision 0f0727134d937799ce4c2ea5116ee75a228375f0 \
  --filter RouterScenarioImportLimitTests
```

This command is expected to fail the intended pre-decoding assertions. It is a
prior-method-body control, not a full historical product build. Its source hashes
and explicit substitution are recorded; the ordinary next run restores staged
candidate sources.

The limits apply to this byte-import API. Direct use of JSONDecoder bypasses
these raw-byte safeguards. Caller-owned input Data already exists before the
check, and arbitrary work inside an application's valid route decoder cannot
be bounded by JSON screening. Native parity and the complete S08 resource
contract remain separate gates.

Fresh recovery control: the PR54 method body above compiled and ran 12 tests,
producing 32 intended boundary assertions while the valid byte-boundary and
nested-envelope controls passed. Restoring the current method passed all 81
Testing functions. The initial wrong filter selected no tests and was rejected
by the runner; that attempt is recorded as a harness failure, not a witness.
